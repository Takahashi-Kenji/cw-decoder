うまくいかないとき

症状から探せるようにしてあります。まず疑うのはレベルとスケルチです。

文字がまったく出ない

確かめること対処
● デコード開始 を押しましたか いちばん多い原因です。● 開始 だけでは音を取り込むだけで、文字は出ません
レベルメータは振れていますか 振れていなければ入力デバイスの選択か、受信機側の音量を見直します
スケルチが高すぎませんか 橙色の破線が信号より上にあると、信号ごと落ちます。スライダを下げてください
モデルは読み込まれていますか 2 段目の灰色の文字が (未読込) なら、起動時に --ckpt を付けたか確認します

無音なのに文字が出続ける

スケルチが効いていません

メル特徴抽出は音量の情報を捨てるため、ノイズでも増幅されて文字になります。 30 秒の無信号で 38 個のトークンが出た実測があり、しかも確信度は 0.6〜0.7 と高いので、 確信度の閾値では防げません。スケルチを上げてください。

文字は出るが、化けが多い

確かめること対処
BPF は ON ですか。中心周波数は合っていますか スペクトルを見て、CW の横線が通過帯に収まっているかを確かめます。 混信が多ければ帯域幅を 250 Hz 程度まで狭くします
LAN 経由で音を受けていて、BPF を切っていませんか 誤り率 97% まで崩壊します。送り出し側は生の音を流すので、受け側の BPF が要ります
入力が振り切っていませんか 歪みます。受信機側の音量を下げます
モードは合っていますか 和文を欧文モードで読むと、変換表に無い符号がすべて外れます
起動直後の数秒だけ乱れていませんか フィルタが落ち着くまでの過渡です。最初の数秒は割り引いてご覧ください

_ が多い

読めなかった印です。確信度の閾値を下げて消さないでください。 実測で閾値を 0.5 から 0.0 にすると、誤り率が 19.74% から 23.64% へ悪化しました。 _ の裏に正解が隠れているのではなく、間違った文字が出てくるだけです。

まずは信号の質を上げる方（レベル・BPF・スケルチ）を見直してください。 それでも多いときは、その信号がその程度だということです。 LLM 清書が意味を補ってくれることがあります。

自動モードが和文に切り替わらない

ホレ（和文開始）をモデルが取り逃していると、切り替わりません。 実測で、純粋な和文なら検出率 100%、実運用の形（欧文の前置きに続くホレ）では 0% でした。

そのため和文にしかない符号を見たら切り替えるという別の道が用意してあります （設定のデコードタブ）。 これが働くので和文自体は読めますが、ホレの文字は画面に出ません。 うまくいかないときは、モードを 和文 に手で切り替えてください。

動きが重い・固まる

症状対処
受信中に表示が途切れる 設定の確定タブでデコード用リングを広げていませんか。 広げると音声スレッドが止まります。初期値 30 秒に戻してください
清書のときだけ待たされる 正常です。全体の読み直しと LLM の応答待ちが入ります。 応答待ちの上限 で諦めるまでの時間を決められます
GPU にしたのに速くならない このモデルは小さいので、レイヤごとの起動費用の方が勝ちます。 cpu のままで構いません

LLM 清書が動かない

メッセージ・症状対処
Ollama に接続できませんOllama が起動していません。ollama serve を実行します
結果が絵文字や繰り返しになるモデルが小さすぎます。gemma4:e4b をお試しください
流暢だが内容が原文と違う 翻訳特化のモデルを使っていませんか。 流暢な訳文を作る訓練を受けているため、壊れた入力を捏造で埋めます
意味が逆になる小さいモデルで起きます。テンキ ハ ハレ を「天気が悪い」と取った実例があります

送信できない

症状対処
送信 が押せない 確認 を通していません。 本文を編集すると確認は無効に戻ります
接続できない 打鍵側で cw_key_server.py が動いているか、アドレスとポートが合っているかを確かめます
電鍵が動かない・逆に動く --check-lines で結線を確かめ、--key-line / --key-invert で直します
ポートを開いただけで電波が出る USB シリアル変換器が DTR/RTS を H にするためです。 ダミーロードを付けてから確かめてください
本文に ? が入る 差し込み欄が空です。相手コール・相手名前は受信文から拾うので、読み取りが崩れていると入りません

設定をやり直したい

~/.cw-decorder/ の設定ファイルを削除してから起動し直してください。 次回起動時に初期値で作り直されます。 経歴（operator.json）と語彙（lexicon_ja.json）は別ファイルなので、 残したいときはそれらを避けて削除してください。

そもそも、どこまで読めるものか

実受信で測った平常値です。完璧には読めません。

文字の誤り率
欧文およそ 16%

人と比べると

状態の悪い信号で、熟練者が耳で読んで 28.6% 間違えた録音を、モデルは 34.9% で読みました。 足りないのは符号の読み取り精度ではなく、語の推測です。 辞書補正と LLM 清書は、そこを埋めるための仕掛けです。
