# 辞書による即時補正 (LLM を使わない語の訂正)

2026-08-07

## 何を解こうとしたか

LLM 清書はローカル (Ollama) だと 1 回に数秒かかる。受信しながら「早く言葉として
成立させる」用途には遅い。**LLM を使わずに語だけを直せないか**を調べた。

## 誤りの正体は「文字」ではなく「語の切れ目」だった

最初は「符号距離つきの辞書照合で文字を直す」つもりで測ったが、誤った語を並べて
みると想定と違っていた。

```
'?RST599'  → 正解 'CQ'      語が繋がっている
'CQDE'     → 正解 'DE'      語が繋がっている
'CQCQDE'   → 正解 'DE'      語が繋がっている
'?URRST'   → 正解 'RST'     語が繋がっている
'NAM'      → 正解 'NAME'    文字が足りない
'CQRT'     → 正解 'QRT'     文字が余分
```

**多数派は語の切れ目の誤り**である。WORD_BREAK トークンの再現率が 57〜69% しか
ないことの直接の現れで、既知の最大の誤り源と一致する。

そこで対策を 2 つに分けた。

1. **切り直し** — 語彙語の並びに厳密一致で分割する (`CQDE` → `CQ DE`)
2. **寄せ** — 符号距離で最近傍の語彙語へ寄せる (`CQRT` → `QRT`)

## 符号距離であることが要点

寄せ先は**素の編集距離ではなく符号 (・-) の距離**で選ぶ。CW の誤りは
D(-・・) ↔ B(-・・・) のように**点 1 個の差**で起きるので、符号空間で測ると正解が
最近傍に来る。文字空間では D と B は「ただの別の文字」で、距離に情報が無い。

符号は `morse_tokens.py` から逆引きするので、二重定義は無い。

## 結果 (held-out 実録音、`models/full/best_infer.pt`)

| | CER | 差 |
|---|---|---|
| 補正なし (現行) | 19.25% | |
| 切り直しのみ | 17.15% | −2.09pt |
| 寄せのみ | 17.99% | −1.26pt |
| 切り直し + 寄せ (歯止め前) | 16.74% | −2.51pt |
| **出荷値 (歯止めあり)** | **17.15%** | **−2.09pt** |

和文は語彙が別なので未対応。**±0.00pt で悪くはならない**。

計算はマイクロ秒なので hop (0.5 秒) ごとに走らせられる。LLM の往復は要らない。

## 壊さないための歯止め

`?` を消す方向の変更なので、確信度閾値を下げたときと同じ罠がある
(閾値 0.5 → 0.0 で CER が 3.9pt 悪化した件)。次の 4 つで守っている。

1. **数字を含む語は触らない** — コールサイン (JH0ILL)・RST (599)。
   存在しない局を自信ありげに作るのは `?` より悪い
2. **プロサイン `[SK]` 等は触らない** — 語ではなく運用記号
3. **2 位との差 (margin) を要求する** — 語彙は 2〜3 文字の略語が密集していて
   最近傍がすぐ入れ替わる
4. **末尾の `?` が本物なら守る** — 下記

実測で、正しかった語を壊した数は **0**。

### margin が実際に効いている例

```
?UR  → 1位 CUL(0.70)  2位 PWR(0.77)  margin 0.07  → 寄せない
```

最近傍の `CUL` は**誤り**である。margin の歯止めが無ければ、正解 `UR` を捨てて
`CUL` を自信ありげに表示していた。

```
QSC  → 1位 QSB(0.40)  2位 QSY(0.40)  margin 0.00  → 寄せない
```

同距離で決め手が無い。どちらかを選ぶより `?` のまま残す方が良い。

### `?` の二重の意味

`?` は「読めなかった」印であると同時に、**符号表にある実在の文字** (・・--・・)
でもある。`QSL?` の `?` は本物の疑問符で、消すと意味が変わる。テキストだけを見て
両者は区別できない。

**末尾の `?` を外すと語彙語になるなら、その `?` は本物**と判定している。語の残りが
既に正しいなら、その `?` はその語のデコード失敗ではないからである。
この歯止めを入れ忘れると `QSL?` → `QSL` と削り、実測で 0.42pt 悪化した。

## 測定の限界

- **欧文の held-out は 10 件 57 語しかない。** しきい値も同じデータで選んでいるので
  数字は楽観側に出る
- ただし `max_distance` を 1.2〜2.0、`margin` を 0.2〜0.5 と振っても CER が動かない。
  knife-edge に合わせた値ではない
- **和文は未対応。** 語彙 (定型表現) を別に用意する必要がある

## 実装

- `src/infer/word_correct.py` — 補正本体。語彙 `EUROPEAN_LEXICON` は**ここが唯一の
  真正ソース**で、LLM プロンプトの参考語彙 (`src/llm/prompt.py`) もこれを参照する
- `src/app/main_window.py` — 確定テキスト受信時に適用し、補正箇所を橙色で表示
  (元の姿はツールチップに残す)。チェックボックス「辞書補正」で切替
- 設定 `word_correct_enabled` (既定 True)

補正後のテキストが LLM 清書にも渡るので、LLM が直すべき誤りが減る。
