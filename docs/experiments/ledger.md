## 書き方

- **仮説の列を書けない run は回さない。** これが「夜間に回し放題にした結果、
  何が効いたか分からなくなる」への唯一の歯止めである。
- コマンドは**そのまま**貼る。現行モデル (`models/full/best.pt`) の学習コマンドが
  正確に残っておらず、対照実験に設定ドリフトの疑いが残っている。同じことを繰り返さない。
- 数値は `scripts/eval_model.py` の **モード別 TER** を写す。全体 TER だけでは

  `<ckpt-dir>/meta.json` と ckpt の `extra` に残す。転記元はそちら。

### 20260825_l4_first — L4 データは効くか

> **注記 (2026-08-27)**: この実験の学習データには **held-out と本文が重なる L4 が
> 18 件**入っていた (held-out 20 件のうち 2 件ぶん = 物差しの 10%)。
> `scripts/split_real_data.py --exclude` は後から作ったもので、この時点では
> 本文の重複を確認していなかった。**下の数値はその分だけ甘い。**
> 相対比較 (ctrl_1k と l4_1k の差) は同じ汚染を共有するので成立する。

**仮説**: 実受信機チェーンのラベル付きデータ (L4、1200 件 4.26 時間) を足すと、
held-out の TER が下がる。**ただし L4 は機械打鍵なので和文には効きにくいはず**
(L4 上の和文 TER 14.55% に対し held-out 和文 27.15% = 難しさの主因は打鍵の揺らぎ)。

**データ**: 本文単位で分割 (同じ文が train と val の両方に入らないこと)

| | 件数 | 備考 |
|---|---|---|
| L4 train | 1015 | ユニーク本文 616 |
| L4 val | 185 | ユニーク本文 84、重なり 0 |
| 実録音 train | 72 | data/ft/real_train |
| 実録音 val | 18 | data/ft/real_val (FT の best 選択用) |

**共通**: 起点 `models/full/best.pt` / batch 16 / lr 5e-5 / `--mix-synth --real-ratio 0.5`
/ tone 500±60 / `--num-workers 0` / seed 42 / eval-dir は 3 本とも同じ `data/ft/real_val`

| run | データ | steps |
|---|---|---|
| ctrl_1k | 実録音 72 のみ | 1000 |
| l4_1k | 実録音 72 + L4 1015 | 1000 |
| l4_2k | 実録音 72 + L4 1015 | 2000 |

**判定**: `models/eval/baseline_v4.json` (欧文 13.06% / 和文 27.15% / synth 45.16%) に対し
① 和文が改善 ② 欧文の悪化が +0.5pt 未満 ③ synth_val の悪化が +3pt 未満。

**注意**: L4 の 1200 件は先頭 1 文字が落ちる収録上の欠陥を含む (93%)。
`--lead-in-s` で修正済みだが、このデータは修正前に録ったもの。
3 本とも同じデータを見るので**相対比較は成立する**。

#### 結果 (2026-08-25)

| run | 欧文 TER | 和文 TER | 備考 |
|---|---|---|---|
| baseline (`best_infer.pt`) | 13.06% | 27.15% | 実録音 90 件で FT 済 |
| ctrl_1k (実録音 72) | 16.33% | 30.32% | **対照群。同じレシピで 3.2pt 悪化** |
| l4_1k (72 + L4 1015) | 15.92% | 28.96% | 対照群比 −1.36pt |
| l4_2k (同、2000 step) | 16.73% | 30.77% | step を伸ばすと効果が消える |

**対照群が baseline より 3.2pt 悪い**のが最大の学び。違いは実録音 90 → 72 件だけ
(18 件を val に取り分けた)。**L4 の効果を baseline と比べていたら「悪化した」と
誤読していた。**

#### 訂正 (同日、語間バイアスを入れて測り直した)

上の「L4 の効果は −1.36pt」は**語間の過剰挿入に覆い隠された値**だった。
モード別バイアス (docs/word_break_bias_by_mode.md) を入れて測り直すと:

| bias | ctrl_1k 和文 | l4_1k 和文 | L4 の効果 |
|---|---|---|---|
| 0 | 30.32% | 28.96% | −1.36pt |
| −3 | 27.15% | 24.89% | −2.26pt |
| −8 | 23.53% | **18.10%** | **−5.43pt** |

CER では bias −8 で 30.52% → 18.47% (−12.05pt)。

**教訓: 交絡している欠陥を先に取り除かないと、施策の効果を過小評価する。**
朝の時点で「L4 データ 1 件の価値は自局録音の 1/50 以下」と結論しかけたが、
これは誤りだった。語間の欠陥を直してから測るべきだった。

### 20260826_full_v4a — 土台から実データを混ぜる (P4-A)

**仮説**: 土台のフル学習 (102,000 step) は合成 100% で実録音を 1 件も見ていない。
L4 2204 件 + 実録音 72 件を `--real-dir` で土台から混ぜると、FT の 1,000 step
では届かない露出が得られ、held-out の TER が下がる。

**前提として直したこと**

1. **助走のオーグメンテーション** (`--real-lead-in-max 2.0`)。8/24 の 1200 件は
   符号の 60ms 前から録音が始まっており、93% の録音で 1 文字目が落ちる。
   **音は欠けていない**ので、ノイズ床をランダム長で前置すれば使える。
   現行モデルでの実測 (8/24 の 60 件):

   | | 前回の固定貼り合わせ (ad2a391) | 今回 |
   |---|---|---|
   | TER | 15.69% → 16.97% (悪化) | 15.69% → **13.02%** |
   | 置換 | 46 → **98** | 46 → **47** |
   | 脱落 | 86 → 34 | 86 → 54 |
   | 先頭脱落 | — | 57/60 → **22/60** |

   **健全なデータでは軽く悪化する** (8/25 +0.96pt / 実録音 +0.29pt)。
   それでも全データに掛ける — 8/24 だけに掛けると「長い助走 = 5W セッション」
   という相関が残り、モデルがそれを手がかりにできてしまう。

2. **本文単位の取り分け** (`scripts/split_real_data.py`)。実測で
   **8/24 と 8/25 は同じ 700 本文**だと分かった (5W と 50W で同じ原稿)。
   件数で割ると同じ本文が train と val の両方に入る。

3. **held-out と本文が重なる 18 件を学習から除外**。held-out 20 件のうち
   **2 件が L4 の本文と重なっていた** (物差しの 10%)。
   **8/25 の FT 実験 (20260825_l4_first) は既にこの状態で回っており、
   台帳のあの値はその分だけ甘い。**

**データ**

| | 件数 | 本文 |
|---|---|---|
| `--real-dir data/ft/v4/train` | 2276 (L4 2204 + 実録音 72) | 710 |
| `--keyed-dir data/ft/v4/val` | 196 (L4 178 + 実録音 18) | 78 |

train ∩ val = 0 / train ∩ held-out = 0 / val ∩ held-out = 0 (実測)。

```bash
python scripts/train.py --steps 102000 --batch-size 16 --lr 3e-4 --num-workers 4 \
  --noise-dir data/noise/train \
  --real-dir data/ft/v4/train --real-ratio 0.2 \
  --real-lead-in-min 0.0 --real-lead-in-max 2.0 \
  --keyed-dir data/ft/v4/val --best-metric keyed \
  --eval-interval 500 --seed 42 --ckpt-dir models/full_v4a
```

スクラッチ (warm start しない) / 定常 2.2 sps / 所要見込み 13.5 時間。

**判定**: `models/eval/baseline_v4.json` (欧文 13.06% / 和文 27.15% / synth 45.16%)
に対し、held-out で ① 和文が改善 ② 欧文の悪化が +0.5pt 未満 ③ synth_val の
悪化が +3pt 未満。**best.pt と last.pt の両方を測る** (keyed val は L4 が
196 件中 178 件を占めるので、best が L4 寄りに選ばれている可能性がある)。

**この run には対照群が無い。** 比較先の `models/full/best.pt` は学習コマンドが
残っておらず設定ドリフトの疑いがある。**改善が出た場合は、`--real-dir` を
抜いた同一コマンド (合成のみ 12.6 時間) を対照群として回してから採否を決める。**
悪化した場合は対照群を回す必要はない。

### 20260826_head_hallucination — 先頭幻覚の原因 (学習を回さずに決着)

**仮説 (計画書 P0.5)**: 「ゼロ → ノイズ床の段差」が合成側にだけ無く、
モデルがこの段差をキーダウンと取り違えている。

**結果: 否定。** 段差を作る (先頭にノイズ床を足す) と**悪化**し、ゼロパッドを
剥がしても数値が 1 ビットも動かなかった。

**真の原因は学習分布の偏り**である。合成は符号が中央 0.14 秒で始まるのに
実信号は中央 1.38 秒待つ。先頭を合成の分布に寄せる (0.14 秒に切り詰める) と
**学習なしで TER 19.74% → 18.45% / 先頭誤り 24 → 11 個**。

影響の大きさも計画書の見積り (~0.4pt) と 1 桁違い、**実測 5.15pt**
(held-out の誤り 92 個のうち 24 個が先頭 2 トークン以内、うち 18 個が挿入)。

詳細と全掃引結果は `docs/head_hallucination_cause.md`。

**教訓**: 「先頭幻覚」と一括りにすると逆向きの 2 つの問題を取り違える。
L4 8/24 は助走が足りずに**脱落**、held-out は助走が足りていて**挿入**。
助走を足すと前者は治り後者は悪化する。**症状の名前ではなく向きで分けること。**

#### 結果 (2026-08-27) — **不採用**

| run | 欧文 TER | 和文 TER | 全体 | synth_val |
|---|---:|---:|---:|---:|
| baseline_v4 (現行・FT 済) | **13.06%** | **27.15%** | 19.74% | 45.16% |
| base_noft (FT 前の旧土台) | 17.55% | 29.41% | 23.18% | — |
| full_v4a best.pt (step 96000) | 49.80% | 47.06% | 48.50% | 44.69% |
| full_v4a last.pt (step 102000) | 49.39% | 38.91% | 44.42% | 45.11% |

判定 3 条件のうち ①和文が改善 ②欧文の悪化 +0.5pt 未満 の**両方を大きく外した**。
③ synth_val は 45.11% で基準内 (45.16% → −0.05pt)。→ **不採用**。

**FT の有無では説明できない。** 現行モデルは手打ち 90 件で FT 済みだが、
**FT 前の旧土台 (23.18%) と比べても 21pt 悪い**。

**モデルは壊れていない。** 合成欧文 1.23% / 合成和文 0.83% / L4 val 1.68% /
synth_val 45.11% (baseline と同等)。**held-out の手打ち録音だけが壊滅的**である。

#### 何を学んだか

**1. 学習中の keyed val が役に立たなかった (最大の教訓)**

keyed val は 1.68% と言い続けたが、held-out は 44.42% だった。**26 倍外した。**
原因は val の 196 件中 178 件が L4 で、**学習データと同じ 2 セッション・同じ
受信機・同じ原稿生成器**だったこと。本文だけ分けても、それ以外が同一なら
**汎化ではなく当てはまりを測ることになる**。

→ **val は「学習データと違う源」から取らなければ意味がない。**
実信号 val を作るなら手打ち側から取り分けるべきだった。

**2. L4 特化は「効かない」ではなく「壊す」形で現れた**

計画書のリスク欄は「L4 を大量に入れても手打鍵 TER が下がらないのは想定内」と
書いていた。実際は**下がらないどころか 2 倍以上悪化**した。実データ 2,276 件の
うち 2,204 件 (97%) が L4 (単一受信機・オートキーヤー) で、抽選の 20% を
占めていた。**土台から混ぜる比率が高すぎた。**

**3. 先頭の onset は原因の一部にすぎない**

先頭を合成の分布 (0.05 秒) に切り詰めると 44.42% → 35.84% に改善するが、
baseline の 19.74% には遠い。`docs/head_hallucination_cause.md` の対策は
必要だが十分ではない。

#### 次にやること (この run の後始末)

1. **手打ち 72 件で FT して回復するか** (25 分)。baseline は FT で
   23.18% → 19.74% を得た。同じレシピで回復すれば「土台は無事、FT が
   欠けていただけ」、回復しなければ「土台が壊れた」と分かる
2. 回復しない場合は `--real-ratio` を 0.2 → 0.05 程度に下げて再学習
3. **実信号 val を手打ち側から取り直す** (今回の物差しは機能しなかった)

### 20260827_p3_operating_point — 動作点の判別 (学習なし)

**仮説**: 受信音から (WPM, 文字間, コントラスト) を測れば、モデルの得意な動作点に
振り分けられる。

**結果: 合格。** モデル選択に効く 2 軸 (文字間・コントラスト) で 3 動作点を
leave-one-out 最近傍セントロイド (閾値の手調整なし) で **98.8%**。

| 動作点 | 集合 | 文字間 | コントラスト | 判別率 |
|---|---|---:|---:|---:|
| 弱・狭 | 旧録音 72 + L4 5W 119 | 3.35〜3.54 | 8.4〜9.0 dB | 99.5% |
| 強・狭 | L4 50W 120 | 3.26 | 16.4 dB | 98.3% |
| 強・広 | held-out 20 | 4.38 | 28.4 dB | 95.0% |

**WPM は判別に使わない。** L4 は意図的に 15〜30 WPM を混ぜており、4 集合を
3 軸で分けようとすると 79〜92% で安定しない。合成が 8〜50 WPM を覆うので
どのモデルも速度には対応している。効くのは学習データの間隔とコントラストの偏り。

**弱信号の WPM は +15% 高く出る** (適応閾値の偏り)。表示に使うなら補正が要る。

#### 結果 (2026-08-28)

基準 = wabun: held-out 21.24% (欧文 16.33 / 和文 26.70) / l4_weak 0.53% / l4_val 3.36% / Head<2 28 個 (挿入 15)。

| run | held-out | 欧文 | 和文 | l4_weak | l4_val | Head<2 (挿入) | synth_val | 判定 |

### 20260828_p2d_wordspace — 語間の詰まった局で語間がゼロになる穴

**運用者の報告**: 「文字は取れるのに欧文のスペースがまったく無い。baseline でも同じ」。

**原因 (実測)**: 合成の語間が **7.0 固定** (`hand_keying=False` の分岐は `KeyingParams` の
既定値。文字間 3.0 固定と同じ穴)。語間を振った合成 (22 WPM / SNR 15 dB / 語間 15 個) で:

| 相手局の語間 (dot) | baseline (bias 0/−1/−5) | p2b |
|---|---|---|
| 7.0 | 15/15/15 | 15/15/15 |
| 6.0 | 15/15/13 | 15/15/10 |
| **5.0** | **0/0/0** | **1/1/0** |
| 4.5 | 0/0/0 | 0/0/0 |

**5 dot 以下ではどのモデル・どのバイアスでも語間がゼロ。** 6 との間に崖がある。
モデルは「3 なら文字間、7 なら語間」しか知らず、5 を文字間に倒す。
バイアスの問題 (自動モードの −5) とは**別の、より根本的な穴**。
既存の包絡線検出 (`detect_word_breaks_from_audio`) はきれいな 7 dot の合成でも 15 個中
2 個しか拾えず、代替にならない。

**仮説**: p2b のレシピに `--word-space 4.5 12.0` を足して FT すれば、文字間 (2.6〜5.0)
と重なる範囲を**その局の文字間に対する相対**で学び、5 dot の語間でも出るようになる。
held-out (語間 9.5 / 文字間 4.4) で過剰にならないことも同時に見る。

```bash
scripts/finetune.py --resume models/full/best.pt --data-dir data/ft/combined_ja \
  --eval-dir data/l4/val60 --steps 1000 --lr 5e-5 --batch-size 16 --mix-synth \
  --real-ratio 0.5 --tone-center 500 --tone-span 60 --num-workers 0 --seed 42 \
  --best-saturation 0 --pre-silence 0.0 2.5 --word-space 4.5 12.0 --ckpt-dir models/p2d_wordspace
```

**判定**: 3 集合で p2b と同等 (l4_weak +1pt 以内 / held-out 悪化 +1pt 以内) かつ
合成の語間 5.0 dot で 15 個中 12 個以上出ること。最終判定は運用者の実受信 (録音待ち)。

#### 結果 (2026-08-28) — p2d は**このままでは不採用**

| | held-out | 欧文 | 和文 | l4_weak | l4_val | Head<2 |
|---|---:|---:|---:|---:|---:|---:|
| p2b (基準) | 16.31% | 11.02% | 22.17% | 0.80% | 1.43% | 7 |
| p2d (+語間 4.5〜12) | 19.53% | 13.47% | 26.24% | 0.66% | 1.62% | 9 |

l4_weak は保ったが **held-out が +3.2pt 悪化** (和文 +4.1pt)。文字間の広い局
(held-out 4.4 dot) で語間が出過ぎる。

**運用者の録音 (JA1ABC/3、23 WPM) で分かった本質**: この局は文字間 4.3 dot に対し
語間 5〜6 dot で、**差が 1 dot 未満**。絶対値でも相対値でも間隔だけでは分けられない
(p2d は語間 0〜1 → 4〜7 個に増えたが `JG3U VN/3` と語の中で切れる)。
包絡線 + 相対閾値 (文字間 + max(1, 25%)) は held-out で precision 43%、
大津の閾値は 52% / recall 50% でどちらも不十分。

→ **間隔ではなく語彙で切る** (`src/infer/word_correct.py` の「語の切れ目」) を次に試す。
運用者の設定は `word_correct_enabled: False` で欧文の補正がオフだった。

p2d の語間掃引 (合成 22 WPM / 語間 15 個、bias 0/−1/−5): 語間 5.0 dot で **12/11/3**
(baseline 0/0/0、p2b 1/1/0)、4.5 dot で 2/2/0、7.0 で 15/15/15。**絶対値の崖は塞がる**
(文字間 3.0 の局には効く) が、文字間 4.3 / 語間 5 の局には効かず、held-out で悪化する。
候補として残す (`models/p2d_wordspace/`)。既定にはしない。

#### 決着 (2026-08-28 夕) — 語彙で切る

`segment_european_loose` (`16780dc`) + `word_split_enabled` (`68f52c0`、既定 ON、寄せと独立)。
運用者の録音 2 本の出力に掛けた結果:

| 入力 (モデルの出力) | 分割後 |
|---|---|
| `QDEJA1ABC/3JA1ABC/3JCC2IM0Z/PK188+K` | `Q DE JA1ABC/3 JA1ABC/3 JCC 2IM0Z/PK 188 + K` |
| `…CQCQCQDEJA1ABC/3JGSAUVN F3JCC2308/PK188+KD E JH` | `… CQ CQ CQ DE JA1ABC/3 JGSAUVN F3JCC 2308 /PK 188 +KD E JH` |

**切った結果は寄せに流さない** (流すと Q → K、/PK → OP と壊れた)。
コールサインは接尾 2 文字以上・プレフィックスに英字 (CC2I / 599NAME を弾く)。
語彙に JCC / JCG を追加。**最終判定は運用者の実受信。**
