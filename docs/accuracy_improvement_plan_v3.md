## 0. 3 行まとめ

1. 目標は 欧文 15.9% → **15%** (残り −0.9pt)、和文 31.7% → **15%** (残り **−16.7pt**)。
   実質的に**和文を半減させる計画**である。
2. **和文 15% は人間の耳の素の読み取り (28.57%) より 13pt 良い数字。**
   音響モデルの改善だけでは構造的に届かない。**言語モデルによる語推測が必達施策**になる。
3. 実録音の入手難は「**素材移植合成**」で回避する。統計量を真似るのではなく、
   実受信音から**素材そのもの** (背景ベッド・打鍵タイミング・包絡線・受信機の癖) を
   切り出して移植する。学習前に**難しさ再現チェック**で必ず検収する。

## 1. 改善幅の予算配分 (和文 −16.7pt をどこで稼ぐか)

| # | 施策 | 和文 期待幅 | 欧文 期待幅 | 種別 |
|---|---|---:|---:|---|
| ① | WORD_BREAK 適応閾値 (後処理) | −2〜3pt | −1pt | 推論側 |
| ② | 素材移植合成 + FT | −3〜5pt | −1〜2pt | データ+学習 |
| ③ | 自局追加打鍵 (和文重点) + FT | −1〜2pt | −0.5pt | データ+学習 |
| ④ | フル再学習 (メル分解能・括弧トークン) | −1〜2pt | −0.5pt | 学習 |
| ⑤ | **LM 融合 (語推測)** | **−5〜8pt** | −1〜2pt | 推論側 |
| | **合計** | **−12〜20pt** | −4〜6pt | |

- 合計レンジの中央で目標 −16.7pt に届く計算。**⑤が最大項**であり、⑤抜きでは
  楽観値でも届かない。⑤を後回しにしない
- 欧文は ①か⑤のどちらかが少し効けば達成。**計画の実体は和文対策**である
- 各期待幅は実績からの外挿 (辞書補正 −2pt、2 段階確定 −2.3pt、実信号 FT −2.7pt 等)。
  施策ごとに held-out で実測し、この表を更新していく

## 2. 基本方針 (やらないことを先に決める)

| 方針 | 根拠 |
|---|---|
| ✅ 実受信音から**素材を移植**して合成する | 統計量一致では転移しない (§7-4)。移植なら統計に表れない構造ごと運べる |
| ✅ LM 融合を必達施策として先行着手 | 和文 15% は人間の耳より良い数字。語推測なしには構造的に不可能 |
| ✅ 学習前に「難しさ再現チェック」で検収 | 合成器は仮説を数分で否定できる道具 (§9-6)。10 時間の学習を賭ける前に潰す |
| ❌ パラメトリックな合成分布拡張はしない | A, B〜D, G の 3 系統すべて失敗。実測統計を移しても TER 3% にしかならない |
| ❌ FT 済みモデルへの追い FT はしない | 実験 F の敗因。FT は常に `models/full/best.pt` から |
| ❌ 代理指標で判断しない | 一致率掃引で結論が逆になった前例 (§9-2) |

## 4. Phase 0 — 素材移植合成パイプライン

### 4.0 素材源

「実際のアマチュア局の録音を得るのは難しい」の正体は**録音ではなくラベルの不足**である。
素材抽出 (4.1〜4.3) はラベル不要なので、素材源には次が使える:

- **KiwiSDR / WebSDR 公共受信機網** — 世界中の実 CW トラフィックを録音し放題。
  バンド・時間帯・受信機を変えて多様な伝搬条件を集める
- 自局受信機の常時録音 (コンテスト・パイルアップ・QRM 密集帯を含む)

### 4.1 移植する素材の 4 層

| 層 | 素材 | 抽出法 | ラベル |
|---|---|---|---|
| L1 | **背景ベッド** (ノイズ・QRM・QSB・空電) | CW 無し区間の切り出し、または狭帯域ノッチで信号を消した残差 | 不要 |
| L2 | **打鍵タイミング系列** | 包絡線検出で on/off 時系列を抽出。要素長を短点/長点プールに分け、**系列順を保ったまま**新テキストへ再割当 | 不要 |
| L3 | **包絡線テンプレート** | 実要素から立上り/立下り波形・キークリック・チャープを切り出しテンプレート化 | 不要 |
| L4 | **実受信機チェーン** | 合成 CW でオシレータをキーイング → **実受信機で受けて録音** (AGC ポンピング・フィルタリンギング・非線形歪みが乗る) | **自明** (送ったテキスト = ラベル) |

- L2 の要点: 従来合成の敗因候補は iid ジッタ。実打鍵の「徐々に間延びする」
  「特定文字の癖」という**相関構造**は統計量に出ない。系列ごと移すことで運ぶ
- L4 は設備があれば**一晩回しでラベル付きデータを無制限に量産**できる。
  B〜D (実ノイズ混合) の失敗が「ノイズだけでは足りない」ことを示している以上、
  受信機の癖まで通す L4 が本命候補

### 4.2 検収: 難しさ再現チェック (学習を回す前に必ず)

新パイプラインで生成したデータ 100 件程度を**現行モデル `best_infer.pt` でデコード**する。

| 結果 | 判定 |
|---|---|
| TER 25〜35% (実録音並み) | ✅ 難しさの移植に成功。FT へ進む |
| TER < 10% | ❌ 従来合成と同じ「簡単なデータ」。**学習を回さず棄却** |
| TER > 50% | ⚠ 難しさではなく壊れ方が違う可能性。誤り内訳を確認 |

加えて**誤り内訳の一致**も見る: 実録音は 挿入 48% (うち WORD_BREAK 30%)・置換 31%・
脱落 21%。移植データの内訳がこれに近いほど「同じ難しさ」である確度が上がる。

### 4.3 Ablation 設計 (どの層が難しさを運ぶかの特定)

対照群の原則 (§9-1) に従い、素材を 1 層ずつ足して難しさ再現チェックを繰り返す:

```
従来合成 (基準, TER ~3%)
 → +L1 ベッド → +L2 タイミング → +L3 包絡線 → L4 実機チェーン (別系統)
```

- 各段の TER 上昇分 = その層が運ぶ難しさの量。効かない層は製造コストごと捨てる
- B〜D の失敗は「L1 単独では足りない」の先行証拠として整合するはず

## 6. Phase 2 — LM 融合 (予算⑤、必達施策)

### 6.1 なぜ必達か

人間の耳の素の読み取りは CER 28.57%、モデルとの差は 6.35pt しかなく、両者は同じ箇所を
読み違えている (§6.4)。人間が実用的に読めるのは**文脈から語を推測して直すから**。
和文 15% は素の聴取性能の倍近く良い数字であり、**この「推測」を実装する以外に道がない**。

### 6.2 段階的に上げる

| 段 | 内容 | 状態 |
|---|---|---|
| LM-0 | 和文辞書補正 (405 語、符号列距離) | ✅ 済 (2026-08-14) |
| LM-1 | 語彙拡張 405 → 2,000〜5,000 語 (QSO 頻出語・地名・コールサイン・ラバースタンプ) | 未 |
| LM-2 | カタカナ文字 3-gram LM を**オフライン全文脈デコードの beam search に浅い融合**。上限がどこまで動くか測る | 未 |
| LM-3 | 効果があればリアルタイム側 (2 段階確定の第 2 段) へ移植 | 未 |
| LM-4 | 語 2-gram (定型連鎖「オハヨウ ゴザイマス」等) の追加 | 未 |

- LM 学習コーパス: QSO ログ・和文 QSO 文例集・ラバースタンプ表現集。
  打鍵原稿 (欧文 30 + 和文 60) は held-out と重なるため**コーパスから除外**する
- LM はモデル本体と独立。**再学習不要・トークン ID 制約なし・語彙追加自由**
- 誤補正率を held-out で必ず測る。「実受信で安全な直しのみ」の原則は LM-2 以降も維持
  (確信度の高い音響仮説を LM が上書きしすぎないよう融合重み λ を掃引)

### 6.3 欧文側

欧文は LM-1 相当 (辞書拡張: コールサイン・Q 符号・略語) で残り −0.9pt を取りにいく。

## 7. Phase 3 — FT 反復 (移植合成 + 実録音)

### 7.1 FT レシピ (v2 から継続)

| 項目 | 規定 |
|---|---|
| 起点 | 常に `models/full/best.pt` (FT-on-FT 禁止) |
| step 数 | データ量に比例スケール。90 件 → 1,000 step の実績から **目安 = 件数 × 11 step**、±50% を掃引 |
| lr | 5e-5 基準に 2.5e-5 / 1e-4 の 3 点 |
| 早期停止 | held-out TER。synth_val 悪化 3pt 超で不採用 |
| 対照群 | データ追加効果の測定時は「旧 90 件のみ同 step」を並走 |
| 記録 | 実行コマンドを結果文書へそのまま残す |

### 7.2 データ構成

| 源 | 量の目安 | ラベル |
|---|---|---|
| 既存実録音 | 90 件 / 24.8 分 | あり |
| L4 実機チェーン録音 | 数時間規模まで量産可 | 自明 |
| L1+L2+L3 移植合成 | 検収合格した層構成でオンザフライ生成 | 自明 (テキストは生成側) |
| 自局追加打鍵 (和文重点) | +50〜100 件 | あり (音声照合してから採用、§4.1 の教訓) |

- 混合比は掃引で決める (実録音:移植合成 = 0.5:0.5 を初期値に、実験 E の real_ratio に倣う)
- **held-out は従来の 21 件を凍結維持** + 新規 20 件 (和文重点) を追加し両方を報告。
  移植合成は held-out に入れない (自作データで自己採点しない)

### 7.3 学習曲線でデータ効率を測る

データ量を段階的に増やして 件数 vs TER の曲線を引く。寝てきたら LM 側 (Phase 2 の
LM-4 以降) へ重心移動。1 回 9〜30 分なので掃引コストは小さい。

## 8. Phase 4 — フル再学習 (一度だけ)

### 8.1 Gate 条件

1. 速い和文の文字抜け診断が完了 (メル分解能変更の要否が決まる)
2. 移植合成パイプラインが検収合格している (フル学習のデータ源に組み込むため)
3. 語彙の見直しが確定している

### 8.2 同時実施項目

- [ ] 和文括弧 `「` (`-・--・-`) / `」` (`・-・・-・`) を語彙へ追加
- [ ] 語彙 72 トークンの棚卸し
- [ ] (診断次第) メル窓 25ms/hop10ms → 15ms/hop5ms。系列長 2 倍の学習時間・RTF 影響を
      小規模学習で先に見積もる
- [ ] 学習データに検収済み移植合成を混合 (従来合成 100% からの脱却)
- [ ] 学習後: `export_tokens.py` / `export_onnx.py` / `export_golden.py` 再実行
- [ ] **実行コマンドを結果文書に残す**
- [ ] 完了後、Phase 3 レシピで実録音 FT → 次の現行モデル

### 8.3 モデル容量

hidden 256 → 384 等の増量は、L4 で実質無制限のラベル付きデータが得られるように
なった場合のみ再検討。それまでは見送り (過学習リスク)。

## 10. リスクと撤退基準

| リスク | 兆候 | 対応 |
|---|---|---|
| 移植合成が難しさを運べない | 検収 TER < 10% | その層構成は棄却。学習は回さない (検収がある限り損失は製造コストのみ) |
| L4 の受信機の癖が自局特化になる | 他受信機録音の held-out で悪化 | 受信機設定 (帯域・AGC) を振って多様化、または KiwiSDR 経由の L4 変種を追加 |
| LM が音響仮説を上書きしすぎる | 誤補正率上昇、欧文悪化 | 融合重み λ を下げる。「安全な直しのみ」原則へ回帰 |
| LM 期待幅 −5〜8pt が過大 | Phase 2 後に和文 24% 未達 | 予算再配分。L4 量産 + モデル容量増の再検討へ |
| 適応 WORD_BREAK が synth を壊す | synth_val +3pt 超 | 不採用。挿入対策は LM 側へ委ねる |
| メル hop 5ms で RTF 悪化 | RTF > 0.3 | hop 7.5ms の中間案、または CNN に時間 stride 追加 |
| フル再学習の再現失敗 | 合成固定評価が 0.00%/2.48% に届かない | 旧設定と diff。届くまで採用しない |
