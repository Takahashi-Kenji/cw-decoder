## 1. 評価集合 — どれも「特異」である

**中立な評価集合は存在しない。** どの集合も、どれかのモデルにとって地元である。
これを忘れると「held-out で悪い = 壊れている」と誤読する (実際に 2 回誤読した)。

| 集合 | 件数 | WPM | 文字間 (dot) | コントラスト | 助走 | 素性 |
|---|---:|---:|---:|---:|---:|---|
| **held-out** (`data/keying_scripts`) | 20 | **28.8** | **4.38** | **28.4 dB** | 1.38s | 運用者の打鍵をアプリで録音。欧文 10 / 和文 10、466 トークン |
| **旧録音** (`data/ft/real_{train,val}`) | 90 | 20.1 | 3.13 | 9.0 dB | 0.48s | 同じく運用者の打鍵。held-out と同じ原稿群の別サブセット |
| **L4 8/24** (`data/l4/20260824_5w_18m`) | 1200 | 24.3 | 3.24 | **11.7 dB** | 0.06s | 自局送信 5W を自局で受信。**助走 60ms の収録欠陥あり** |
| **L4 8/25** (`data/l4/20260825_50w_18m`) | 1200 | 24.3 | 3.24 | 22.5 dB | 2.16s | 同 50W。助走の欠陥なし |
| **合成** (学習の 80%) | ∞ | 8〜50 | **3.0 固定** | — | 0〜0.3s | `MorseSynthDataset` |

**教科書値は 文字間 3.0 / 要素間 1.0 / 語間 7.0。**

### 分かったこと

- **「手打ち vs 機械打鍵」という区別は成り立たない。** 実測すると要素長のばらつきは
  L4 の方が大きい (長音σ 0.509 対 旧録音 0.153)。違うのは**動作点**
  (速度・間隔・コントラスト) である
- **held-out は最も速く (28.8 WPM)、最も間隔が広く (4.38)、最もきれい (28.4 dB)**。
  20 件・1 環境の標本にすぎない
- **合成は文字間 3.0 の 1 点しか作っていなかった。** `hand_keying=False` の分岐が
  `KeyingParams` の既定値を使うため。**学習した 163 万サンプルすべてが 3.0**
  → held-out の 4.38 は**一度も見たことのない値**だった (2026-08-27 発見・修正済)

## 2. モデルの系統

```
旧土台  models/full/best.pt  (2026-06-12, 合成のみ 102,000 step)
  ├─ +旧録音 90 件 FT 1,000 step ──────────→ baseline  models/full/best_infer.pt
  └─ +combined_ja FT 1,000 step ──────────→ wabun     models/wabun/best_infer.pt
                                              (旧録音 90 + L4 8/24 649、和文 709/739)

合成 80% + 実 20% でフル学習 102,000 step (旧土台とは無関係にスクラッチ)
  ├─ 実 = L4 2,204 + 旧録音 72、助走増強あり → full_v4a  models/full_v4a/
  └─ 実 = L4 8/25 1,102 のみ、助走増強なし  → full_v5   models/full_v5/
        └─ +裾野拡張 FT 1,000 step ────────→ ft_v5_wide models/ft_v5_wide/
```

| モデル | ファイル | 手法 | 学習した実データ |
|---|---|---|---|
| 旧土台 | `models/full/best.pt` | フル 102k | なし (合成のみ) |
| **baseline** (第 4 版まで配布) | `models/baseline_v4/best_infer.pt` | FT 1k | 旧録音 90 |
| **wabun** | `models/wabun/best_infer.pt`<br>(= `models/ft/l4_ja/best.pt`) | FT 1k | 旧録音 90 + L4 8/24 649 |
| full_v4a | `models/full_v4a/{best,last}.pt` | フル 102k | L4 2,204 + 旧録音 72 |
| full_v5 | `models/full_v5/{best,last}.pt` | フル 102k | L4 8/25 1,102 |
| **ft_v5_wide** | `models/ft_v5_wide/last.pt`<br>`cw_v5wide.onnx` | full_v5 + FT 1k | L4 8/25 1,102 |
| **p2b** (2026-08-28、**第 5 版で配布** = `models/full/best_infer.pt`) | `models/p2b_presilence/cw_p2b.onnx` | wabun のレシピ + `--pre-silence 0 2.5` | 旧録音 90 + L4 8/24 649 |
| p2c (2026-08-28) | `models/p2c_all/cw_p2c.onnx` | 同 + `--char-space 2.6 5` + `--intra-space 1 1.5` | 同 |

実行コマンドは各 `<ckpt-dir>/meta.json` と `docs/experiments/ledger.md` にある。

## 4. 実運用での所見 (運用者)

**2026-08-28: `p2b` が最も誤り率がなく、正確度が高く信頼できる** (wabun / p2c / 他と聴き比べ)。
3 集合の合格と実受信の判断が一致した初めてのモデル。アプリの弱・狭の既定推奨を p2b にした。

**2026-08-27: `wabun` が実受信で断然良い** (p2b が出る前の判断)。

数値と整合する。`wabun` は **L4 8/24 (5W・コントラスト 11.7 dB) で 0.53%** と
突出しており、実際の交信で受かる他局の信号は自局 50W ループバックや自局の打鍵録音
より弱いのが普通だからである。

**held-out はこれを予測できなかった** (`wabun` を 21.24% = baseline より悪いと評価)。
**held-out は実運用の物差しではない。**

## 5. 何が効いて何が効かなかったか

### 効いたもの

| 施策 | 効果 |
|---|---|
| **短い FT (1,000 step)** | 3 回とも成功。旧土台 → baseline / wabun / ft_v5_wide |
| **旧録音 90 件を残すこと** | `wabun` は残して成功。full_v4a/v5 は外して失敗 |
| **合成の裾野拡張** (文字間 2.6〜5.0 / 先頭無音 0〜2.5s) | held-out 34.12% → **17.38%**、先頭誤り 24 個 → **3 個** |
| **wabun + 先頭無音の拡張だけ** (p2b) | L4 弱の強さを保ったまま held-out 21.24% → **16.31%**、先頭誤り 28 → **7**。**両方の土俵で強い初のモデル** |
| **語間バイアスのモード別化** (2026-08-25) | 再学習なしで 欧文 −1.22pt / 和文 −4.07pt |

### 効かなかったもの

| 施策 | 結果 |
|---|---|
| **実データを土台から混ぜるフル学習** | **2 回とも失敗** (held-out 44.42% / 34.12%)。合成のみの旧土台 23.18% にも負ける |
| **L4 を大量に入れること単独** | L4 では強くなるが他の動作点を壊す |
| 助走のオーグメンテーション | 8/24 の欠陥救済には有効 (−2.67pt) だが、健全なデータでは悪化 (+0.29〜0.96pt) |

## 6. 測り方について踏んだ穴 (再演を防ぐため)

1. **val が学習データと同分布だと意味がない。**
   full_v4a の学習中 val は **1.68% と言い続けたが held-out は 44.42%。26 倍外した。**
   val 196 件のうち 178 件が L4 で、学習と同じセッション・同じ受信機だった。
   本文だけ分けても、それ以外が同一なら**汎化ではなく当てはまりを測る**
2. **飽和した val で best を選ぶと運になる。** L4 val は 0.06% まで飽和し、
   評価ごとに ±4pt 揺れた。`full_v5` は **best.pt (46.57%) が last.pt (34.12%) より
   12pt 悪い**
3. **ファイル名で分けても本文で重なる。** L4 の 2 セッションは同じ 700 本文を
   5W と 50W で録ったもの。件数で割ると同じ本文が train と val の両方に入る
4. **held-out の 2 件が L4 と本文重複していた** (物差しの 10%)。
   2026-08-25 の FT 実験はこの状態で回っており、台帳のあの値は甘い
5. **重みの距離で系統を判断してはいけない。** FT は 1,000 step で大きく動くので
   「どちらに近いか」は起点を示さない。**`meta.json` の記録を見ること**

## 7. 未解決

- **語間の詰まった局の語の切れ目** (2026-08-28)。運用者の録音 (JA1ABC/3) は文字間 4.3 /
  語間 5〜6 dot で差が 1 dot 未満 — 間隔では原理的に切れない (p2d は候補止まり)。
  → `segment_european_loose` で**語彙とコールサインの型で切る** (`word_split_enabled`、既定 ON)。
  `QDEJA1ABC/3JA1ABC/3JCC2IM0Z/PK188+K` → `Q DE JA1ABC/3 JA1ABC/3 JCC 2IM0Z/PK 188 + K`。
  **実受信での確認待ち**

- **中立な評価集合が無い。** L4 で「ゆったり打つ」動作点 (文字間 4.4 前後) を
  録れるようにするには送信側の改修が要る (`src/tx/encoder.py` の間隔が定数固定)
- **合成では実受信の難しさを再現できない。** held-out のタイミングをそのまま
  合成すると full_v4a は 10.09% だが、本物の録音では 44.42% だった
- **配布物の更新**: p2b を配布用 (`models/full/best_infer.pt` / web の ONNX) に据えるかは運用者の判断待ち
- **欧文が犠牲になっている。** `ft_v5_wide` は和文 −7.69pt の代わりに欧文 +2.45pt

## 8. 使い方

```powershell
# 起動 (モデルを指定。p2b が 2026-08-28 に運用者の実受信で採用されたもの)
python scripts/run_app.py --ckpt models/p2b_presilence/cw_p2b.onnx --net-source 192.168.0.10

# 起動後は画面のコンボボックス (登録モデル: p2b / full_v5 / ft_v5_wide / wabun / p2c /
# baseline のうち実在するもの) で切り替えられる。任意のファイルは「読込…」から (*.onnx *.pt)。
# ステータスバーに受信音の動作点と得意なモデルが出る:
#   例「文字間 3.3 / 9 dB → 弱信号・狭い間隔 (p2b)」 (? は境界に近く確信なし)
# **自動では切り替えない。** 推奨と実際の選択が一致するか記録が溜まってから (計画 v5 P4-3)

# 同じ録音を複数モデルで比べる (ライブでは音声の入り口を 2 つ開けない)
python scripts/compare_models.py --wav japanese:録音.wav `
  --ckpt p2b=models/p2b_presilence/cw_p2b.onnx `
  --ckpt wabun=models/wabun/best_infer.pt
```
