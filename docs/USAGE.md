# 取扱説明書 — cw-decoder

AI モールス信号デコーダ **cw-decoder** の使い方です。
受信した CW（モールス信号）の音を、欧文・和文のテキストにリアルタイム変換します。

> まだインストールが済んでいない方は、先に
> **[インストールマニュアル（INSTALL.md）](./INSTALL.md)** を参照してください。

---

## 1. 起動する

PowerShell で `cw-decoder` フォルダに移動し、仮想環境を有効にしてからアプリを起動します。

```powershell
cd $HOME\Documents\cw-decoder
.\.venv\Scripts\Activate.ps1
python scripts/run_app.py --ckpt models/full/best_infer.pt
```

「CW デコーダ」ウィンドウが開きます。

> `--ckpt models/full/best_infer.pt` を**付け忘れない**でください。
> 省略すると未学習モデルで動き、まともにデコードできません。

デコードは既定で **CPU** を使います。GPU はローカル LLM（清書）に空けるためですが、
実測では CPU の方が速いので損はありません。

| デバイス | 30 秒ぶんのデコード | hop 0.5 秒に対する余裕 |
|---|---|---|
| CPU 4 スレッド（既定） | 112 ms | 3.7 倍 |
| CUDA | 139 ms | 2.9 倍 |

モデルが小さいため、GPU はレイヤごとの起動費用の方が勝ちます。
どうしても GPU を使いたいときは `--device cuda` を付けてください。

受信機を繋いだ PC と、このアプリを動かす PC が**別のマシン**でも使えます。
その場合は [11. 受信機が別の PC にあるとき](#11-受信機が別の-pc-にあるとき-lan-経由) を参照してください。

## 2. 画面の説明

ウィンドウは上から **操作バー（上段・下段）** → **デコード結果（左）とレベルメータ（右）** →
**スペクトログラム** の順に並んでいます。

### 上段の操作バー

| 表示 | 役割 |
|---|---|
| **入力デバイス** | 音を取り込むマイク／ライン入力を選びます |
| **モード** | `欧文` / `和文` / `自動` を選びます（→ 4 章） |
| **確信度閾値** | 自信のない符号を「?」にする厳しさ。スライダーで調整（初期値 0.50） |
| **開始** | 音声の取り込みを始めます（まだデコードはしません） |
| **停止** | 音声の取り込みを止めます |
| **● デコード開始** | 押すとデコードが始まります。もう一度押すと停止（■ デコード停止） |

### 下段の操作バー

| 表示 | 役割 |
|---|---|
| **チェックポイント** | 使用中のモデルファイル名。`読込…` で別モデルに差し替え可能 |
| **読込…** | モデルファイル（`.pt`）を選び直します |
| **● 録音開始** | 受信中の音声を WAV に録音します（→ 6 章） |
| **スペクトログラム表示** | 下部の周波数表示の ON/OFF |
| **未確定も表示** | 確定前の文字をグレーで出します（初期値 OFF）。文脈が増えると読みが変わるため、通常は OFF の方が読みやすい |
| **辞書補正** | CW 定型語彙で語を切り直し・寄せします（初期値 ON、→ 5.4 節） |
| **BPF** | 帯域通過フィルタ。CW の音以外のノイズを除去（初期値 ON） |
| **中心 / 帯域** | BPF の中心周波数と通過幅（初期値 600 Hz / 400 Hz） |

### 中央・下部

| 表示 | 役割 |
|---|---|
| **デコード結果**（左の大きな枠） | 確定した文字は**黒**、辞書補正で直した箇所は**橙色**（マウスを乗せると元の姿が出ます）。「未確定も表示」を ON にすると確定前の文字が**グレー**で出ます |
| **レベルメータ**（右の縦バー） | 入力音量の目安。**橙色の破線がスキッシュ（無音）の判定ライン**（→ 5 章） |
| **スペクトログラム**（下） | 周波数の時間変化。**短点と長音が見分けられる分解能**にしてあるので、符号そのものを目で追えます（約 3 秒ぶんを表示）。入力レベルや BPF の調整にも使えます |

デコード結果は**更新のたび末尾までスクロール**します。受信中は常に最新行が見えます。

**3 秒以上の無音があると改行が入ります。** 送信のターンの切れ目で行が分かれるので、
交信の往復が読み取りやすくなります。**和文の段落（`。`）でも改行します。**

**確定は 2 段階です。** 受信中は約 2 秒遅れの速い確定で文字が出ます。相手の送信が
終わる（＝3 秒の無音でターンが閉じる）と、**そのターン全体を広い文脈でデコード
し直し、行を一度だけ書き直します**。書き直しは相手が打ち終わった直後に走るので、
読んでいる途中の行が揺れることはありません（実測で誤り率が下がります。→ 下記）。

> **送信ダイアログを開いている間も、メイン画面は操作できます。**
> 受信を見ながら返信を書いたり、送信中にデコードを止めたりできます。
> ウィンドウの横幅を控えめにしてあるのは、2 つを並べて置けるようにするためです。
> **[送信…] を何度押しても、送信ダイアログは 1 つだけです**（打鍵側は 1 つしか
> 繋がないため）。

## 3. 基本の流れ

受信機をパソコンの入力につないだ状態で、次の順に操作します。

```
1. 入力デバイスを選ぶ
2. モードを選ぶ（欧文 / 和文 / 自動）
3. [開始] を押す          ← 音が取り込まれ、レベルメータが動き出す
4. レベルとフィルタを調整   ← メータが振れすぎ／振れなさすぎない程度に（→ 5 章）
5. [● デコード開始] を押す ← ここからデコード結果が出ます
6. CW を受信              ← 黒（確定）とグレー（暫定）で文字が出ます
7. [■ デコード停止] → [停止]
```

> **ポイント：[開始] だけではデコードされません。**
> 必ず **[● デコード開始]** を押してください。
> 「音は来ているのに文字が出ない」ときは、ここを押し忘れていることがほとんどです。

---

## 4. モードの選び方

CW は同じ符号でも、欧文と和文で表す文字が違います。受信内容に合わせてモードを選びます。

| モード | 使う場面 |
|---|---|
| **欧文 (european)** | 英数字・記号の通信（一般的な DX、コンテスト等） |
| **和文 (japanese)** | カナの和文通信 |
| **自動 (auto)** | 欧文・和文が混ざる QSO。**ホレ（和文開始）** を受けると和文へ、**ラタ（和文終了）** を受けると欧文へ自動で切り替わります |

迷ったときは、欧文中心なら `欧文`、和文中心なら `和文`、両方やり取りする QSO なら `自動` が便利です。
モードは受信中いつでも切り替えられます。

## 5. レベルとフィルタの調整

きれいにデコードする鍵は「適切な入力レベル」と「ノイズ除去」です。

### 入力レベル

レベルメータ（右の縦バー）を見ながら、受信機やパソコンの音量を調整します。
信号が来たときにメータが**中ほどまで振れる**くらいが目安です。
小さすぎると拾えず、大きすぎる（振り切る）と歪みます。
入力レベルの多少のばらつきは、内部の特徴量抽出が自動で正規化するため気にしなくて構いません。

### スキッシュ（無音の判定ライン）

レベルメータの**橙色の破線**がスキッシュ（無音判定）のラインです。
入力がこの線より下のときは「無音」とみなし、デコーダに無音を流し込んでノイズを
文字化しないようにします。**メータ横の縦スライダ**で動かせます（−60〜0 dB、
下端の −60 で実質無効）。値は設定ファイルに保存されます。

**初期値は −25 dBFS です。** 判定は **BPF 通過後**のレベルで行います。生の入力レベルでは
無信号時 −28 dBFS・信号時 −40〜−10 dBFS と範囲が重なって分離できませんが、
ノイズの大半は帯域外なので BPF 後なら差が開きます。

> **スキッシュは必ず入れてください。** メル特徴抽出は音量情報を捨てるため、
> 無信号のノイズでも増幅されて文字として出ます。30 秒の無信号で 38 個もの
> トークン（ほとんど `[SN]`/`[SK]`）が出た実測があり、しかも確信度は 0.6〜0.7 と
> 高いので確信度閾値では防げません。**デコーダの手前で止めるしかありません。**

ノイズは状況で変わるので、受信中でもスライダで調整できます。
**下げすぎるとノイズを拾い、上げすぎると弱い信号が丸ごと落ちます。**

### BPF（帯域通過フィルタ）

**BPF を ON** にすると、CW のトーン付近だけを通し、それ以外のノイズを除きます。
混信やノイズが多いときに効果的で、「?」が減ります。

| 設定 | 目安 |
|---|---|
| **中心** | 受信している CW トーンの高さに合わせます（初期値 600 Hz） |
| **帯域** | 狭いほどノイズに強い反面、調整がシビアになります。初期値 400 Hz、混信が多ければ 250 Hz 程度まで狭く |

スペクトログラムで、CW の横線が BPF の通過帯（中心 ± 帯域の半分）に収まっているか確認すると調整しやすいです。

### 辞書補正（LLM を使わない即時補正）

**「辞書補正」チェックボックス**（初期値 ON）で、確定テキストの語を CW の定型語彙に
照らして直します。計算はマイクロ秒なので、受信しながら 0.5 秒ごとに効きます。

直す内容は 2 つです。

| 種類 | 例 |
|---|---|
| **語の切れ目**（多数派） | `CQDE` → `CQ DE`、`CQCQDE` → `CQ CQ DE` |
| **文字の誤り** | `CQRT` → `QRT`、`TNZ` → `TNX` |

文字の寄せ先は**符号（・-）の距離**で選びます。CW の誤りは D(-・・) ↔ B(-・・・) のように
点 1 個の差で起きるので、符号の近さで測ると正解が最近傍に来ます。

**補正した箇所は橙色**で表示され、マウスを乗せると元の姿が出ます。

実測（held-out 実録音の欧文）で CER 19.25% → 17.15%（−2.09pt）。和文は語彙が別なので
未対応ですが、悪くもなりません（±0.00pt）。

> **触らないものがあります。**
> **数字を含む語**（コールサイン `JH0ILL`、RST `599`）と**プロサイン** `[SK]` は変更しません。
> 存在しない局を自信ありげに作るのは「?」より悪いためです。
> 語彙の候補が僅差のときも「分からない」として元のまま残します。

## 6. 録音する

受信した音声を WAV ファイルとして残せます。後で聞き直したり、デコードをやり直したりできます。

1. 受信中（[開始] 済み）に **[● 録音開始]** を押します。
2. もう一度押す（**[■ 録音停止]**）と保存されます。
3. ファイルは **`data/real`** フォルダに、デコード結果テキストとモード情報付きで保存されます。

---

## 7. WAV ファイルをあとからデコードする（オフライン）

録音済みや手元の WAV を、アプリを使わずコマンドでデコードできます。
リアルタイムより文脈を広く使えるため、**精度はこちらの方が高め**です。

```powershell
python scripts/decode_user_wav.py --ckpt models/full/best_infer.pt --wav european:data/real/your_file.wav
```

- `--wav` は **`モード:ファイルパス`** の形式で指定します（`european:` または `japanese:`）。
- 複数ファイルをまとめて処理したいときは `--wav` を繰り返し指定できます。
- 結果は画面表示に加え、`decode_result.txt`（UTF-8）にも書き出されます。

> オフラインデコードのモード指定は `european` / `japanese` のみです（`auto` はアプリのライブ専用）。

## 8. LLM 清書（AI による日本語清書）

デコード結果を LLM（AI）に送り、**誤り訂正・略語展開・読みやすい日本語への書き直し**を
1 回の操作で行う機能です。
結果はデコード結果の下の「LLM 清書パネル」に表示されます。

### 清書パネルの読み方

| 文字色 | 意味 |
|---|---|
| **黒** | LLM が「確実に読めた」と判断した箇所（原文どおり） |
| **赤** | LLM が推測・補正した箇所（誤り訂正・略語展開・欧文化などを行った部分） |

赤い部分は LLM の推測ですので、重要な内容は元のデコード結果と照らし合わせて確認してください。
赤が多くて読みにくいときは **「推測を赤で表示」** を OFF にできます（本文はそのまま出ます）。

### 2 つの清書モード

清書は**増分方式**です。**一度清書した分は二度と送りません。**
そのため結果は消えずに積み上がっていき、読んでいる途中で書き換わることもありません。

| モード | いつ動くか | 用途 |
|---|---|---|
| **まとめて清書**（ボタン） | 押したとき。未清書分を 1 回で全部 | 腰を据えて読み返すとき |
| **自動清書**（チェックボックス） | **文の区切りが来たとき**、そこまでを短く | 受信しながら追うとき |

自動清書が区切りとみなすのは次の 3 つです。どれも**文として完結した位置**なので、
途中で切るより自然な日本語になります。直前の分は「参考」として渡され、話が繋がります。

| 区切り | 備考 |
|---|---|
| **改行**（3 秒以上の無音） | 送信のターンの切れ目 |
| **`、`**（和文の区切点） | 改行は滅多に起きないため、句読点でも区切ります |
| **`。`**（和文の段落＝文の終わり） | 同上 |

> `?` は区切りにしていません。符号表に `?` はありますが、**`?` は「読めなかった」印
> としても出る**ため、区切りにすると読めない文字ごとに清書が走ってしまいます。

区切りが来ない長い送信のために、約 20 秒の間隔でも動く保険があります。

**最初からやり直したいとき**は「クリア」を押してから「まとめて清書」を押してください
（クリアで清書の進捗が 0 に戻ります）。

### LLM が行う処理

| 処理 | 内容 |
|---|---|
| **誤り訂正** | 受信誤りによる欠落・文字化けを文脈から補います（欧文・和文とも） |
| **略語展開** | CQ・RST・QTH・OM・TNX・73 などをわかりやすい日本語に展開します |
| **日本語清書** | カタカナ交じりの文を漢字かな交じりの読みやすい文に整えます |
| **欧文化**（和文モード時のみ） | コールサイン・RST・数字など、欧文として意味が通る部分を欧文に変換します |

> 欧文・自動モードでは「欧文化」は行われません。

### 操作パネルの説明

デコード結果パネルの下に、次の操作パネルが表示されます。

| 操作 | 役割 |
|---|---|
| **プロバイダ**（ドロップダウン） | `ollama` / `openai` / `claude` から LLM を選びます |
| **モデル名**（ドロップダウン・入力可） | `ollama` のときは**インストール済みのモデルを自動で一覧**します（小さい順） |
| **まとめて清書**（ボタン） | 未清書分を 1 回で全部清書します |
| **クリア**（ボタン） | 清書パネルを消し、進捗を最初に戻します |
| **自動清書**（チェックボックス） | 文の区切りごとに短く清書します |
| **短いプロンプト**（チェックボックス） | 小さいローカルモデル向けの短い指示を使います（初期値 ON、→ 下記） |
| **推測を赤で表示**（チェックボックス） | 赤が多くて読みにくいときに OFF にできます |

### 「短いプロンプト」について

LLM への指示を 207 文字に絞ります（通常版は 1403 文字）。**和文にだけ適用されます。**

小さいローカルモデルには重い指示が害になります。実測では、2B のモデルが入力を無視して
**指示に書いた例文をそのまま返し**、4B のモデルが「チューリップ」を捏造し、「おはよう」を
落としました。短い版ではどれも直りました。

欧文は通常版のままです。欧文に必要なのは「触らない規律」で、それは通常版の
**捏造禁止・確実さ優先**に書いてあります（コールサインや RST を作られると実害が出ます）。
短縮数字の規則と無線語彙も通常版に置いてあります。

### Ollama（ローカル・無料）を使う

Ollama はご自分のパソコン上で動くため、**API キーが不要**でインターネット接続なしでも使えます。
ただし、別途 Ollama 本体のインストールが必要です。

**準備手順**

1. ブラウザで [https://ollama.com](https://ollama.com) を開き、**Windows 版をダウンロード**してインストールします。
2. PowerShell でモデルを取得します。

```powershell
ollama pull gemma4:e4b
```

3. Ollama を起動します（インストール後は通常自動起動しますが、起動していないときは次のコマンドで起動できます）。

```powershell
ollama serve
```

4. アプリのプロバイダを `ollama` にすると、**入っているモデルが自動で一覧**されます。
   モデルを選んで「まとめて清書」を押してください。

**どのモデルを使うか**

2026-08-08 に held-out の和文で比べた結果です。**大きさは質を保証しません。**

| モデル | 速度 | 結果 |
|---|---|---|
| **gemma4:e4b** | **0.8 秒** | **ローカルでは最良**。「天気は晴れです。暑いです」 |
| gemma3:4b | 0.9 秒 | 不可。`テンキ ハ ハレ`（晴れ）を「天気が悪い」と逆に取る |
| qwen3.5:2b | 1.6 秒 | 破綻。絵文字の羅列と繰り返し |
| gemma3:12b | 11.8 秒 | 大きいのに悪い。記号の暴走と謝罪文 |

**翻訳特化のモデルは向きません。** `translategemma` は
`オハヨウ、アツイ デス、シカタ ナイ` を「こんにちは。お元気ですか？今日はいい天気ですね」と
**流暢に捏造**しました。翻訳モデルは「流暢な訳文を作る」訓練を受けており、
こちらが欲しいのは「壊れた入力に忠実な変換」です。目的が逆を向いています。

**HuggingFace の GGUF を引くとき**は `hf.co/` の接頭辞と量子化タグの**両方**が要ります。

```powershell
ollama pull hf.co/mmnga/sarashina2.2-3b-instruct-v0.1-gguf:Q4_K_M
```

> `realm host "huggingface.co" does not match original host "hf.co"` というエラーは、
> **リポジトリが存在しないとき**にもこの文言で出ます。まず名前を疑ってください。

### OpenAI / Claude（クラウド）を使う

OpenAI または Claude を使う場合は、**API キーを `.env` ファイルに設定**する必要があります。
設定手順は **[インストールマニュアル（INSTALL.md）の「LLM API キーの設定」節](./INSTALL.md)** を参照してください。

キーを設定したら、プロバイダを `openai` または `claude` に切り替えて「清書」を押します。

既定のモデルは次のとおりです。候補にない名前も手入力できます。

| プロバイダ | 既定モデル | 候補 |
|---|---|---|
| `ollama` | 実機に入っている最小のもの | `/api/tags` から自動取得 |
| `openai` | `gpt-5.6-luna` | `gpt-5` / `gpt-5-mini` / `gpt-4.1` |
| `claude` | `claude-haiku-4-5` | `claude-sonnet-4-6` / `claude-opus-4-8` |

`gpt-5.6-luna` などの推論モデルは**思考が既定でオン**のため時間がかかることが
あります。清書が返ってこない場合は `llm_timeout_s` (既定 120 秒) を延ばすか、
軽いモデルへ切り替えてください。

**「短いプロンプト」はクラウドの大きいモデルでもオンのままにしてください。**
実測 (2026-08-08) で、ローカル・OpenAI・Claude の**3 つすべてで短い版が勝ち**ました。
`gpt-5.6-luna` は短い版の方が速く (3.3 秒 対 6.8 秒) かつ忠実で、重い版は平文で
「何か聞きます」と捏造しました。`claude-haiku-4-5` の重い版は `こちらは好様` という
崩れを出し、`[ホレ]` を「こんにちは」と誤読しました。

清書の質と速さの実測は `docs/llm_refine_result.md` にあります。
現時点の最良は **`claude-haiku-4-5` (1.0 秒/件)**、ローカルなら **`gemma4:e4b`** です。

### LLM 清書がうまくいかないとき

| 症状 | 対処 |
|---|---|
| ステータスバーにエラーが出て清書が表示されない | エラー内容を読んでください（下表参照）。**生デコード結果は消えません** |
| `Ollama に接続できません` などのメッセージ | Ollama が起動していません。`ollama serve` を実行してください |
| `API キーが設定されていません` | `.env` ファイルにキーが入っていません。INSTALL.md の手順で設定してください |
| `タイムアウトしました` | ネットワークが遅い・Ollama が重い場合に出ます。しばらく待って再試行してください |

> **清書が失敗してもデコードは止まりません。**
> 生デコード結果（上のパネル）はそのまま残りますので、受信を続けながら原因を調べられます。

## 9. うまくデコードできないとき

| 症状 | 対処 |
|---|---|
| 文字がまったく出ない | **[● デコード開始]** を押したか確認。起動時に `--ckpt models/full/best_infer.pt` を付けたか確認 |
| ノイズで「?」や変な文字が増える | **BPF を ON** にし帯域を狭める（250 Hz 程度）。スキッシュの破線をノイズのすぐ上へ |
| 弱い信号を拾えない | 入力レベルを少し上げる。スキッシュの破線を下げる |
| 短い符号（E, T, A, N など）が不安定 | **確信度閾値を下げる**（0.2〜0.3）と「?」が減ります。欧文の短符号はもともと揺らぎやすい特性です |
| 和文なのに欧文の文字が出る | モードが `欧文` のままかも。`和文` か `自動` に切り替え |
| 1 語が不自然に分割される | 受信側の語間が広いと起こります。気になる場合はオフラインデコード（7 章）で確認 |
| 起動直後の数秒が乱れる | フィルタの状態が落ち着くまでの過渡。**最初の数秒**は割り引いて見てください |

> **リモートデスクトップ（RDP）経由では正しくデコードできません。**
> 音声圧縮で CW の点・線の長さが崩れるためです。
> リアルタイムデコードは、**受信機をつないだパソコンで直接**アプリを動かしてください。
> RDP は画面操作だけに使ってください。

## 10. 設定の保存場所とリセット

調整した内容（モード、閾値、デバイス、BPF、スキッシュ、辞書補正、清書の設定、
ウィンドウ位置など）は、アプリ終了時に自動保存され、次回起動時に復元されます。

設定にはスキーマ版があり、**上げたときは「旧既定のままの項目」だけが新既定へ移行**します。
自分で値を変えていた項目は書き換えません。

保存先：

```
C:\Users\<ユーザー名>\.cw-decorder\settings.json
```

設定を初期状態に戻したいときは、アプリを閉じてからこのファイルを削除（または名前変更）し、
アプリを起動し直してください。次回起動時に初期値で作り直されます。

## 11. 受信機が別の PC にあるとき（LAN 経由）

受信機を繋いだ PC と、デコードする PC が別でも使えます。
無線機は無線室に、PC は書斎に、といった構成や、受信機側が非力な PC の場合に使います。

```
受信機 ── 音声ケーブル ── PC-A（送信役）
                              │  LAN（家庭内ネットワーク）
                              ↓
                          PC-B（cw-decoder 本体・画面を見る側）
```

音声は**圧縮せずそのまま**流します。通信量は 1 秒あたり約 32 kB（256 kbps）で、
家庭内 LAN なら無視できる量です。

> **リモートデスクトップの音声転送は使わないでください。**
> 音声が強く圧縮され、1000 Hz より上がほぼ失われます。まともにデコードできません。
> この機能はそれを迂回するために用意しています。

### 準備（PC-A 側）

PC-A には cw-decoder 一式が入っていれば十分です。**GPU も深層学習のライブラリも不要**で、
音を取り込んで送るだけの軽い処理しかしません。

### 手順

**① PC-A（受信機を繋いだ側）で送信を始める**

まず入力デバイスの番号を調べます。

```powershell
python scripts/audio_send.py --list
```

```
入力デバイス:
  [0] Microsoft サウンド マッパー - Input  (2ch, 44100 Hz)
  [12] マイク (Realtek HD Audio Mic input)  (2ch, 44100 Hz)
  [13] ライン入力 (Realtek HD Audio Line input)  (2ch, 44100 Hz)
```

**受信機を繋いだ端子**の番号を選びます。多くの場合「ライン入力」です。

```powershell
python scripts/audio_send.py --device 13
```

起動すると、PC-B で打つコマンドがそのまま表示されます。

```
入力デバイス : 13
取り込み     : 44100 Hz → 16000 Hz モノラル
待ち受け     : 0.0.0.0:45678
  GPU 側の PC では:  python scripts/run_app.py --net-source 192.168.1.20:45678

接続を待っています… (Ctrl+C で終了)
```

接続されると、送っている時間とレベルが 1 秒ごとに表示されます。

```
接続: 192.168.1.30:54445  — 送信を開始します
  送信    12.3 秒   lvl  -35.2 dB
```

**この `lvl` の値を必ず確認してください。** −110 dB より小さい場合、音が入っていません
（デバイス番号が違う、ケーブルが抜けている、受信機の音量が絞られている、など）。

**② PC-B（画面を見る側）でアプリを起動する**

`--net-source` に PC-A の IP アドレスを指定します。

```powershell
python scripts/run_app.py --ckpt models/full/best_infer.pt --net-source 192.168.1.20
```

ポートを変えた場合は `--net-source 192.168.1.20:45000` のように書きます。

起動したらステータスバーを確認してください。次のように出ていれば繋がっています。

```
capture started @ 16000 Hz → 8000 Hz (LAN 192.168.1.20:45678)
```

あとは通常どおり「開始」→「デコード」で使えます。**BPF は必ず ON** にしてください。

なお LAN を使っているときは、画面の入力デバイス選択は無効になります（PC-A 側で選ぶため）。

### 止めるとき・切れたとき

- 送信側を Ctrl+C で止めて起動し直しても、**PC-B 側は操作なしで自動的に繋ぎ直します**
- PC-A を先に起動しておく必要はありません。PC-B を先に起動しても、繋がるまで待ち続けます

> **注意**: 現在のバージョンでは、**通信が切れても画面には何も表示されません**。
> デコードが止まったまま表示が固まります。文字が出なくなったら、
> PC-A 側の送信が動いているかを確認してください。

### うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 「転送元に接続できません」と出る | PC-A で送信スクリプトが動いているか。IP アドレスは合っているか。ファイアウォールがポート 45678 を通しているか |
| 「ポート番号を間違えていませんか」と出る | `--net-source` のポート番号と、送信側の `--port` が一致しているか |
| 接続はできるが文字が出ない | PC-A 側の `lvl` 表示。−110 dB より小さければ音が入っていない。デバイス番号を選び直す |
| 文字は出るが読めない | **BPF が ON になっているか**。これが最も多い原因です |
| デバイスを選ぶと `Invalid device` で落ちる | 一覧に出ても開けないデバイスがあります。別の番号を試してください |

### セキュリティについて

音声は**暗号化せずに流れます**。家庭内 LAN での利用を前提としています。
インターネットに公開されるポートには絶対に割り当てないでください。
待ち受けるアドレスを絞りたい場合は `--bind 192.168.1.20` のように指定できます。

## 12. 無線機が別の PC にあるとき（LAN 経由の送信）

無線機を繋いだ PC（**打鍵側**）が実際に電鍵と PTT を操作し、cw-decoder 本体を動かす
PC（**GPU 側**）のアプリから、書いた文字を渡して打たせます。11 章の受信とは別の LAN
接続です（音声を受け取る向きと、文字を送り出す向きが逆）。

```
無線機 ── 電鍵/PTT ケーブル ── PC-A（打鍵側・cw_key_server.py）
                              │  LAN（家庭内ネットワーク）
                              ↓
                          PC-B（cw-decoder 本体・[送信…] ダイアログ）
```

### 初めて繋ぐとき（必ず読むこと。電波が出ます）

> **無線機の電源を切るか、ダミーロードを付けてから始めてください。**
> 多くの USB シリアル変換器は、**ポートを開いた瞬間に DTR/RTS を H にします。**
> 上がると、**開いただけでキャリアが出ます。**

**① PC-A（打鍵側）で結線を確かめる**（テスターか LED を当てて見る）

```powershell
python scripts/cw_key_server.py --port COM3 --check-lines
```

電鍵線と PTT 線が 1 秒ずつ交互に ON/OFF します。上がらない・逆に動くようなら、
`--key-line` `--ptt-line`（ともに `DTR`/`RTS`。PTT だけは `NONE` も選べます）と
`--key-invert` `--ptt-invert` で直してから、もう一度確かめてください。

> `--check-lines` は `--dry-run` と一緒には使えません。結線確認には実際のポートが
> 要るためで、組み合わせるとエラーで止まります。

**② 無線機の電源を入れず、`--dry-run` で PC-B のアプリから通してみる**

```powershell
python scripts/cw_key_server.py --dry-run
```

`--dry-run` はシリアルに一切触らないモードです。無線機やケーブルなしで、PC-B 側の
アプリから下記「ふだんの使い方」を一通り（接続 → 文章を書く → `[確認]` → `[送信]`）
練習できます。

**③ ここまで通ってから、初めて無線機を繋いでください。**

### ふだんの使い方

**PC-A（打鍵側）で打鍵サーバーを起動**

```powershell
python scripts/cw_key_server.py --port COM3
```

起動すると、PC-B のアプリで入れる `host:port` が表示されます。

```
結線     : COM3  電鍵 DTR / PTT RTS
待ち受け : 0.0.0.0:45679
  アプリの設定に:  192.168.0.10:45679

接続を待っています… (Ctrl+C で終了)
```

**PC-B（cw-decoder 本体）で送信ダイアログを使う**

1. メイン画面の **`[送信…]`** ボタンを押してダイアログを開きます。
2. 「打鍵側:」欄に PC-A の `host:port`（例 `192.168.0.10:45679`）を入れ **`[接続]`**。

   ```
   接続しました — COM3  電鍵 DTR / PTT RTS
   ```

3. 「日本語（漢字かな交じりで可）:」欄に文章を書きます（以下の例では `こんにちは`）。
   下の「送信される文字:」欄に、打鍵側へ送る形（カタカナ、必要なら符号）が自動で出ます。
   「和文をホレ/ラタで囲む」チェックボックス（初期値 ON）で、和文の前後にホレ（和文開始）・
   ラタ（和文終了）を自動で付けるか選べます。
4. 内容を確認し **`[確認]`** を押します（**まだ打鍵しません**）。文字数・要素数・
   所要秒数が出ます。

   ```
   確認しました — 7 文字 / 63 要素 / 6.3 秒
   ```

   この数字は `こんにちは`（ホレ/ラタで囲むと送信される文字は
   `{HORE}コンニチハ{RATA}`）を 20 WPM で送るときの実測値です。**文字数は
   ホレ・ラタをそれぞれ 1 文字と数えます**（`{HORE}` の 6 文字ではありません）。
   速度を変えると秒数も変わるため、**速度を変えると `[確認]` からやり直し**です。

5. **`[確認]` が通って初めて `[送信]` が押せます。** 押すと実際に打鍵が始まります。
6. 途中で止めたいときは **`[中止]`**。

速度は「速度:」欄で指定します（5〜40 WPM、初期値 20 WPM）。ここで選んだ速度は
設定に保存され、次に開いたときも同じ値になります。

> **`[確認]` を押すまで `[送信]` は押せません。編集すると `[確認]` は無効に戻ります。**
> 直前に確認した文字列と、今画面にある文字列が一致しているときしか送れません。
> **速度を変えたときも無効に戻ります**（同じ文でも 5 WPM なら 20 WPM の 4 倍の
> 長さの電波が出るためです）。

> **送信中は Esc でダイアログを閉じられません。** 止めるときは `[中止]` を押して
> ください（画面ごと消えると止める手段がなくなるためです）。

送信が最後まで終わると、次のように出ます。

```
送信しました — 63 要素 / 6.3 秒 / ずれ 最大 1.8 ms
```

要素数と秒数は上と同じ例（`こんにちは` を 20 WPM）の実測値です。「ずれ」は打鍵
タイミングの実測誤差で、PC の負荷によって変わります（数 ms なら正常です）。

### 相手の速度に合わせる（`[受信に合わせる]`）

デコード中は、**受信している信号の速度**をステータスバーの右端に出します。

```
                                        受信 18 WPM
```

送信ダイアログの速度欄の横にある **`[受信に合わせる]`** を押すと、この値が
速度欄に入ります（整数に丸めます）。

> **勝手には追従しません。** 送信の直前に速度が動くと、確認をやり直すことに
> なるためです。押したときだけ入ります。押すと確認は無効に戻ります
> （速度は「何秒間 電波が出るのか」を変えるので、これは正しい動きです）。

**測れないときは何も出しません。** 前の値を残すと、相手が変わっても古い速度が
出たままになり、それに合わせると外すためです。信号が短い・雑音だけ・
極端に速い/遅いといった場合は表示が消えます。

> **これは「だいたいの速さ」です。**
> 運用者の実録音 90 件で台本の WPM と突き合わせた結果、誤差の中央値は
> +1.6%、±10% に収まったのが 78 件でした。**目安としては十分ですが、
> 精密な値としては扱えません。** 手打ちは速度そのものが動きます。

### 起動に少し時間がかかります（正常です）

打鍵側を起こすと、次のように出てから待ち受けが始まります。

```
変換器の準備を待っています… 8 秒
```

**USB シリアル変換器には、ポートを開くたびに Windows が認識し直すものがあります。**
その間（実測で約 7 秒）は、線に命令を出しても反応しません。この待ちを入れずに
送信すると、**電文の最初の数秒がまるごと電波になりません**。運用者の環境では
6.3 秒の和文が、最後の「ハ」とラタしか出ませんでした（2026-08-11）。

そのため**ポートは起動時に 1 回だけ開き、終了するまで開いたまま**にしています。
待つのは起動時の 1 回だけで、以後の送信はすぐ始まります。

変換器がすぐ反応するものなら、待ちを短くできます。

```
python scripts/cw_key_server.py --port COM3 --open-settle-s 0
```

**短くしすぎると最初の文字が欠けます。** `--check-lines` を動かして、
`[1] 電鍵線 ON` の時点で線が反応するかを確かめてから決めてください。

### アプリを使わずに 1 回だけ送る（`--text`）

**PC-B（アプリ側）が落ちているときの、唯一の送信手段です。** LAN も待たず、
PC-A だけで 1 回打って終わります。

```powershell
python scripts/cw_key_server.py --port COM3 --text "CQ DE JA1ABC K"
python scripts/cw_key_server.py --port COM3 --text "CQ DE JA1ABC K" --wpm 25
python scripts/cw_key_server.py --dry-run --text "CQ DE JA1ABC K"    # 練習（電波は出ません）
```

出力（`--dry-run` の実測値）:

```
送信 : CQ DE JA1ABC K
速度 : 20.0 WPM   所要 8.6 秒
完了 : 71 要素   ずれ 最大 0.0 ms / 平均 0.0 ms
```

注意する点は 3 つです。

* **カナ変換はありません。** 漢字・ひらがなは書けません。カタカナと欧文で書きます。
  和文はホレ/ラタも自分で書きます: `--text "{HORE}コンニチハ{RATA}"`
* **`[確認]` にあたる関門がありません。** 実行するとすぐ電波が出ます。初めて試す
  ときは `--dry-run` か、無線機の電源を切った状態で。
* **止めるのは Ctrl+C です。** 押すと電鍵と PTT の線を落としてから終わります。

送れない文字が混じっていると、**打鍵せずに**位置つきで教えて終わります
（`--dry-run` でなくても、ポートは開きません）。

```
エラー: 送信できない文字が含まれています: 髙
  3 文字目: '髙'
```

### 中止の理由・使用中のときは、画面に理由が出ます

送信が完了せず終わったときは、「打鍵側:」欄の下のメッセージで理由が分かります。

| メッセージ | 意味 |
|---|---|
| `中止しました (運用者による中止) — ○ 要素まで送信` | **`[中止]` を押した。** 接続は生きたままです |
| `中断しました — 打鍵側との通信が途切れました (○ 要素まで送信)` | **LAN が切れた。** 接続を切って待機状態に戻ります（→ 次項） |

打鍵側が別の運用者と繋がっているときに **`[接続]`** を押すと、次のように出ます。

```
打鍵側は今、別の運用者が使用中です。しばらく待って再接続してください。(別のアプリが繋がっています)
```

向こうの送信が終われば繋がるようになります。**待機中は 3 秒おきに自動で繋ぎ直す**ので、
何度も `[接続]` を押し直す必要はありません。

### LAN が切れたら

**打鍵は止まります。** 打鍵側は PC-B からの拍が既定 1 秒途絶えると送信を中止し、
**鍵と PTT を両方落とします。** 途中で切れた電文が出ることになりますが、制御を
失ったまま電波を出し続けるよりよい、という設計です。

途中で切れた場合、**続きからの再送信はできません。** もう一度 `[確認]` → `[送信]` で
全文を打ち直してください。

### どうにもならない失敗

* **送信中に USB を抜かれると、ソフトからは線を落とせません。** ポートごと消えるため、
  安全装置（番犬）も届きません。**無線機側で止めるしかありません。**
* **打鍵側の CLI 自体が落ちると、線はドライバの既定に戻ります。落ちる保証はありません。**

心配なときは、無線機側の PTT や電源で物理的に止められることを事前に確認しておいてください。

### うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 「打鍵側に繋がりません」と出る | PC-A で `cw_key_server.py` が動いているか。`host:port` は合っているか。ファイアウォールがポート（既定 45679）を通しているか |
| 「使用中です」と出る | 別の運用者が打鍵側に繋がっています。送信が終わるまで待ってください（自動で繋ぎ直します） |
| 「符号表が両 PC で違います」という警告が出る | 両 PC の cw-decoder のバージョンがずれています。**両 PC のリポジトリを揃えてください** |
| 「送信できない文字があります」と出る | 符号表にない文字が含まれています。文章を書き直してください |
| `[送信]` が押せない | まだ `[確認]` を押していないか、確認後に文章を編集しています。もう一度 `[確認]` を押してください |
| 送信が途中で切れる | LAN が途切れた可能性があります。PC-A 側のネットワークと `cw_key_server.py` が動いているかを確認してください |

### 無線機 PC（PC-A）に要るもの

`pyserial` と `numpy`。**`torch` も `pykakasi` も要りません**（カナ変換はアプリ側、
PC-B で行うため）。

```powershell
pip install pyserial numpy
```

**両 PC の cw-decoder のリポジトリを揃えてください。** ずれていると、接続時に
「符号表が両 PC で違います」という警告が出ます。

### 既定値を変えたいとき

`cw_key_server.py` には、結線や安全装置に関わる引数があります。ふだんは既定値のままで
構いません。

| 引数 | 既定値 | 内容 |
|---|---|---|
| `--key-line` / `--ptt-line` | `DTR` / `RTS` | 電鍵・PTT に使う線（`NONE` は PTT のみ選択可） |
| `--key-invert` / `--ptt-invert` | 反転しない | 極性を反転させたいとき |
| `--ptt-lead-ms` / `--ptt-tail-ms` | `50` / `100` | PTT を先に上げる・遅れて下げる時間（ミリ秒） |
| `--key-watchdog-s` | `5.0` | キー ON が続いてよい上限（秒）。超えると強制的に落とす安全装置 |
| `--max-duration-s` | `120.0` | 1 回の送信の長さの上限（秒） |
| `--lifeline-timeout` | `1.0` | 拍が途絶えたと見なす時間（秒）。前項「LAN が切れたら」の基準 |
| `--listen` / `--bind` | `45679` / `0.0.0.0` | 待ち受けポート・アドレス |

> これらの数値はすべて安全装置に関わるため、`nan` や `inf` のような不正な値を渡すと
> **起動時にエラーで止まります。** 黙って安全装置が無効になることはありません。

## 13. 返信の型（テンプレート）

CQ・応答・締めなど、よく使う文面を前もって書いておき、送信ダイアログの
**`[型を使う]`** で即座に呼び出せる機能です。相手からの受信内容が無い場面
（CQ を出す、締める等）でも、迷わず送信文を作れます。

### 型の置き場所

型は次のファイルに保存されます。

```
C:\Users\<ユーザー名>\.cw-decorder\templates.json
```

**このリポジトリの `docs/reply_templates_example.json` を上のパスへコピーすれば、
10 個の例文からすぐに始められます。**

```powershell
Copy-Item docs\reply_templates_example.json "$HOME\.cw-decorder\templates.json"
```

例文には次の 10 種類が入っています：CQ（欧文・和文）、応答（欧文・和文）、
レポート交換、設備の紹介、天気の話、もう一度お願い、締め（欧文・和文）。

**このファイルが無いと、型の一覧は空のままです。** `[型を使う]` を押すと
「このモードの型がありません（パス）」と出ます。何も起きないように見えたときは、
まずここを確認してください。

### 型を編集する（`[型の編集…]`）

送信ダイアログの **`[型の編集…]`** から、画面で追加・編集・並べ替えができます。

```
型 (上から順に一覧へ出ます)      名前: [応答 (和文)   ]  モード: [和文 ▼]
+------------------------+
| CQ (欧文)   (欧文)      |      本文:
| CQ (和文)   (和文)      |      +--------------------------------+
| 応答 (和文) (和文)      |      | {相手コール} DE {自局コール} … |
+------------------------+      +--------------------------------+
[追加] [複製] [削除]            使える欄: {RST} {QTH} {リグ} …
[上へ] [下へ]                   いまの経歴を差し込んだ下書き:
                                +--------------------------------+
                                | JA1ABC DE JH0ILL {HORE} … {RATA}|
                                +--------------------------------+
```

**一覧の並びが、そのまま送信ダイアログの並びになります。** よく使う型は
`[上へ]` で上に置いてください。

**`[複製]` が便利です。** 似た型を作るのが一番よくある編集なので、
中身ごと写して隣に入れます。

#### 下書き

選んでいる型に**いまの経歴を差し込んだ結果**が出ます。型の本文だけを見ても、
`{リグ}` に何が入るかは経歴次第なので分かりません。**実際に電波へ出る形**で
確かめられます。

#### 保存すると警告が出ることがあります

| 警告 | 意味 |
|---|---|
| **送信できない文字があります** | 一番多いのは `{HORE}` の中に欧文を書いた場合（`{HORE}コンニチハ RST 599{RATA}`）。RST は欧文で送るものなので和文の中では送れません |
| **知らない欄があります** | `{名前まえ}` のような書き間違い。差し込みで置き換わらず、`{` `}` がそのまま残ります |

**警告が出ても保存はされます**（書きかけを残せます）。

#### モード欄

| モード | 一覧に出る画面のモード |
|---|---|
| **欧文** | 欧文・自動 |
| **和文** | 和文・自動 |
| **どちらでも** | すべて |

**画面のモードが `欧文` だと和文の型は出ません。** 全部見たいときは `自動` に
してください。

### 型の `mode` 欄と、一覧に出る型

型ファイルの `mode` は、その型を**どのモードのときに一覧へ出すか**です。

| `mode` | 意味 |
|---|---|
| `"european"` | 欧文の型（本文が欧文中心） |
| `"japanese"` | 和文の型（`{HORE}` … `{RATA}` を含む・和文本文） |
| `"any"` | どちらでも使う型（`PSE AGN AGN K` のような短い欧文の略号） |

**送信ダイアログの「型:」の一覧には、画面上段の「モード:」に合う型だけが
出ます。**

| 画面のモード | 一覧に出る型 |
|---|---|
| 欧文 (european) | `"european"` と `"any"` |
| 和文 (japanese) | `"japanese"` と `"any"` |
| **自動 (auto)** | **全部**（相手に合わせて切り替えるモードなので絞りません） |

> **「例文を入れたのに 5 個しか出ない」ときは、画面のモードを確認してください。**
> 例文 10 個の内訳は欧文 4・和文 5・どちらでも 1 です。欧文モードなら 5 個、
> 和文モードなら 6 個、自動モードなら 10 個すべてが出ます。
> 一覧が空のときは `[型を使う]` を押すと「このモードの型がありません」と
> 保存先のパスが出ます。

**参照するのは「今、画面で選んでいるモード」です**（設定ファイルの値では
ありません）。送信ダイアログを開く前にモードを切り替えれば、その場で一覧に
反映されます。

なお、`[型を使う]` を押したときの **「和文をホレ/ラタで囲む」の自動設定は
`mode` ではなく本文の中身で決まります**。和文（カタカナ・句読点）が入って
いれば囲み、欧文だけなら囲みません。`mode` を `"any"` にした型に和文を書いても
きちんと囲まれます。押した後で手で切り替えれば、その操作が優先されます。

### 差し込める欄

型の本文には、次の `{…}` の形で欄を書いておけます。**`[型を使う]` を押すと、
経歴の値や送信ダイアログの入力欄の値が自動で差し込まれます。**

| 欄 | 差し込まれる値 |
|---|---|
| `{自局コール}` | 経歴（下記）のコールサイン |
| `{名前}` | 経歴の名前 |
| `{QTH}` | 経歴の QTH（所在地） |
| `{リグ}` | 経歴の無線機名 |
| `{アンテナ}` | 経歴のアンテナ |
| `{出力}` | 経歴の出力 |
| `{相手コール}` | ダイアログの「相手:」欄 |
| `{相手名前}` | ダイアログの「相手名前:」欄 |
| `{RST}` | ダイアログの「送る RST:」欄 |

> **`{RST}` は「こちらが相手に与える RST」です。** 相手からもらった RST を
> 書く欄ではありません。相手の RST は自分の耳で受信した内容を見て、
> 「送る RST:」欄に自分で入力してください。

### 欧文はホレの外に置くこと

**和文の型の中で `{HORE}` … `{RATA}` に囲んだ部分には、欧文（英数字）を
そのまま書かないでください。** 和文モールスの符号表には A〜Z がありません。

コールサイン・RST・`CQ`・`73`・`SK` などの欧文の略号は、必ずホレの**外**に
書きます。付属の例文もこの形になっています。

```
良い例: {相手コール} DE {自局コール} RST {RST} {HORE}コンニチハ{RATA} K
悪い例: {相手コール} DE {自局コール} {HORE}RST {RST} コンニチハ{RATA} K
```

悪い例のように書くと、`[型を使う]` の直後に「送信できない文字があります」と
出ます。

**ホレの中でどうしても欧文（リグ名など）を打ちたいときは、次項の `「…」` を
使ってください。**

### 和文の中で欧文を打つ（`「…」`）

リグ名・アンテナ名のような短い欧文を、和文の型（ホレの中）に混ぜて打つときは、
`「` `」` で囲みます。囲まれた中だけが欧文として送られます。

```
{HORE}リグ ハ 「FT991」 デス{RATA}
```

| 符号 | 電波での扱い |
|---|---|
| `「` | 電波には出ません |
| 中身 | 欧文の符号表で送ります |
| `」` | 周りが和文なら、**段落（`・-・-・・`）** として出ます。相手には文の切れ目として届きます。周りが欧文なら出ません |

> **`」` の符号について**
> 本物の閉じ括弧は `・-・・-・`、開き括弧は `-・--・-` で、どちらも和文の符号表に
> 実在します。ただしこのデコーダの符号トークン集合には入れていません
> （足すとトークンの番号がずれ、学習済みモデルの作り直しが必要になるためです）。
> 区切りとしては段落で用が足りるので、当面は段落を出しています。
> **2026-08-12 まで、段落 `・-・-・・` を `」` と誤って表記していました。**
> 電波に出ている符号は当時から変わっていません。

**ホレ・ラタは付けません。** `「…」` の中では和文/欧文を切り替えるプロサインを
送らず、そのまま欧文の符号に変わります。

**閉じ忘れに注意してください。** `「FT991` のように `」` を書き忘れると印として
扱われず、`「` がそのまま「送信できない文字があります」に出ます（`[確認]` の
前に赤字で出るので、気づかずに電波が出ることはありません）。同じ理由で、
`「…」` の区間の中にホレ・ラタを書き間違えて混ぜてしまった場合も「送信できない
文字」として見えます。

**型そのものに `「…」` を書く必要はありません。** 経歴の「リグ」「アンテナ」
「出力」の**読み**欄に `「FT991」` のように書いておけば、型の `{リグ}` などの
欄に自動で差し込まれます。付属の「設備の紹介」は次の形にしてあり、型の側は
リグが欧文であることを知らなくてよいままです。

```
{相手コール} DE {自局コール} {HORE}リグ ハ {リグ}、アンテナ ハ {アンテナ}、シュツリョク ハ {出力} デス、ヨロシク{RATA} K
```

> **`「…」` は経歴の「表示形」（`display`）に書き、「読み」（`reading`）は
> 空のままにしてください**
> （例：リグの表示形を `「FT991」`、アンテナを `「DP」`、出力を `「50W」`）。
>
> **読み欄に入れてはいけません。** 和文の型では読みが使われますが、欧文の型では
> 表示形が使われるため、読みにだけ書くと欧文の型で `{リグ}` が空になります。
> さらに、読み欄にカタカナを入れると**欧文の型がまるごと送れなくなります**
> （読みの辞書がホレ／ラタの境界を無視して本文全体に当たるためです。
> 既知の欠陥で、経歴を欧文・和文の 2 つに分ける作業で解消予定）。

**長音記号 `ー`（のばし棒）は `「…」` の中に入れないでください。** `ー` は
和文の符号表にしか無く、欧文の符号表には無いため、欧文区間の中では
「送信できない文字」になります（例：`「FTー991」` は NG）。**半角ハイフン
`-` は両方の符号表にあるので問題なく送れます**（`「FT-991」` は OK）。
ただし、運用者は実際の交信では記号を省いて `「FT991」` のように打つことが
多いので、書き方の好みとしてもハイフン無しをおすすめします。

**同じ値を欧文の型でも使い回せます。** 欧文の型の中で `「FT991」` と書くと、
括弧が両方落ちて `FT991` だけが送られます。和文用に用意した経歴の値を、
欧文の型にもそのまま使えます。

> **表示形とブラケットの中身をまったく同じ文字列にしないでください。**
> 例えば出力の**表示形**を `50W`、**読み**を `「50W」` のように中身を完全に
> 一致させると、`[型を使う]` の直後に「送信できない文字があります: `「`」
> のように、意味の分かりにくいエラーが出て送れません（実測）。差し込んだ後の
> 文をもう一度「表示形 → 読み」の辞書でスキャンする都合上、差し込み済みの
> `「50W」` の中に残っている `50W` の部分がまた表示形としてマッチし、
> `「「50W」」` と二重に括弧が付いてしまうためです。
>
> **表示形にはハイフンや半角スペースを 1 つ残すなどして、ブラケットの中身と
> 違う文字列にしてください**（例：表示形 `FT-991` / 読み `「FT991」`、
> 表示形 `50 W`（半角スペース入り）/ 読み `「50W」`）。

### 経歴に読みを設定していると、欧文の中で名前・QTH が使えない

**経歴の名前・QTH に読み（カタカナ）を設定していると、欧文の本文に表示形
（例：`TARO`）が出てきた時点で、そこが読み（`タロウ`）へ勝手に置き換わり
ます。** カタカナが 1 文字でも混じると、**その文中の欧文がまるごと
「送信できない文字」になります。** これは `{名前}`/`{QTH}` の欄に限らず、
**型を使わず日本語ボックスへ手で `TARO` と打ち込んだときも同じことが起きます。**

付属の「応答 (欧文)」に `{名前}` `{QTH}` が入っていないのはこのためです。
欧文で名前・QTH を伝えたいときは、経歴の読みを空にしておくか、和文
（`{HORE}` … `{RATA}` の中）で伝えてください。

**危険はありません。** 送信できない状態は `[確認]` の前に赤字で出るので、
気づかずに電波が出ることはありません。

### 経歴（プロフィール）を書いておく

`{自局コール}` `{名前}` `{QTH}` `{リグ}` `{アンテナ}` `{出力}` は経歴から自動で
埋まります。**送信ダイアログの `[経歴…]` ボタン**から書けます。

```
自局コール  [JH0ILL              ]        ← 1 つだけ

            欧文用                和文用
名前        [TARO            ]  [タロウ            ]
QTH         [YOKOHAMA          ]  [ヨコハマシ           ]
リグ        [FT991            ]  [「FT991」          ]
アンテナ    [DP               ]  [「DP」             ]
出力        [50W              ]  [「50W」            ]
```

**欧文用と和文用は「同じものの読み違い」ではなく、別々の値です。**
`「FT991」` は `FT991` の読みではありません。和文の型では和文用が、欧文の型
（と「どちらでも」の型）では欧文用が入ります。

> **自局コールだけは 1 つです。** 和文の交信でもコールサインは欧文で送るため、
> 分ける意味がありません。

**英数字の値は和文用のほうを `「」` で囲んでください。** 囲まないと和文の中で
送れません（`FT991` の `F` `T` は和文の符号表にありません）。**保存すると
画面下に「和文で送れません: リグ の FT」と出る**ので、そこで気づけます。

書いていない欄は**送信文に `?` が出ます**。止めも通知もしません。`?` は和文にも
欧文にも実在する符号で「分からない」を意味するので、そのまま送っても交信は
通ります。**気になる場合は、日本語ボックスの `?` を手で直してから送ってください。**

> **`[確認]` を押すまで送信できないことは変わりません。** 変わったのは
> 「埋まっていない欄があります」で止める仕組みを無くしたことだけです。
> 何が出るかがそのまま見えるようになりました。

保存すると警告が出ることがありますが、**保存そのものは妨げません**（書きかけを
残せます）。

#### 読み辞書

機械変換が外しやすい固有名詞を「語 → 読み」で登録しておけます（`東京` →
`トウキョウ` など）。

> **欧文の語を入れないでください。** 読み辞書は本文全体に当たるため、
> `TARO` → `タロウ` のような行を入れると、**欧文の交信でその語が
> カタカナに化けて送れなくなります。** 保存時に
> 「読み辞書に欧文の語があります」と警告します（入力は妨げません）。

#### 天気と気温

**経歴ではなく送信ダイアログの欄**にあります。相手コールや RST と同じ
「その交信のもの」だからです。**既定は空**にしてあります — 前回の値が残って
いると、書き忘れたまま嘘の天気を送ることになります。

気温は **数字だけ**で書いてください（`20`）。数字は和文・欧文どちらの符号表にも
あるので、型に `キオン ハ {気温} ド` と書けば和文でも通ります。

### 相手コール・相手名前は自動で拾えないことがある

「相手:」欄は、受信内容から自動で拾おうとします。**拾えなかったときは
空のままなので、その場合は手で打ち込んでください。** 「相手名前:」欄は
受信テキストからの推測なので、**当てにしないでください**。とくに人名は
聞き違いが起きやすく、間違ったまま送ってしまうと相手に対して失礼になります。
送信前に必ず内容を確認してください。

## 補足：起動時のコマンドを毎回打つのが面倒なとき

`cw-decoder` フォルダに次の内容のテキストファイルを作り、拡張子を **`.bat`** にして保存しておくと、
ダブルクリックだけで起動できます（ファイル名は自由、例：`デコーダ起動.bat`）。

```bat
@echo off
cd /d "%~dp0"
call .venv\Scripts\activate.bat
python scripts\run_app.py --ckpt models\full\best_infer.pt
pause
```
