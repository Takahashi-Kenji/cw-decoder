# 和文の中の欧文区間 `「…」` 設計書

> **【2026-08-12 追記】この設計書は符号表の誤りの上に書かれている。**
> §3.1 の「`「` はどちらの符号表にも無い。出しようがない」は**誤り**である。
> 本物の括弧は和文表に実在する — 下向き括弧 `「` = `-・--・-`、
> 上向き括弧 `」` = `・-・・-・`。
> また `・-・-・・` は `」` ではなく**段落 (`。`)** である。
> 実装は「区間の閉じで段落を出す」形に直した (電波に出る符号は当初から変わらない)。
> 括弧そのものを足すとトークン ID がずれて再学習が要るため、当面は入れない。
> 詳細は `.claude/CLAUDE.md` の注記を参照。

**経歴の編集画面 (`2026-08-12-profile-editor-design.md`) より先に作る** (§2)。

## 1. なぜ要るか

**和文の交信でも、リグ名やアンテナ名は欧文で送る。**

```
リグ ハ FT991 デス
        ~~~~~ ここだけ欧文
```

いまはこれが送れない。モードが切り替わるのは `{HORE}` / `{RATA}` だけなので、
和文モードの中に `F` や `T` があると「送信できない文字」として弾かれる (実測)。

```
{HORE}リグ ハ FT991 デス{RATA}  ->  NG: FT が送れない
```

**運用者は実際の交信で `「FT991」` と書いている** (2026-08-12 の聞き取り)。
**欧文で短い単語を打つときはホレ・ラタを使わない。**

## 2. なぜ経歴の編集画面より先か

経歴の値 (リグ・アンテナ・出力) は `FT991` `DP` `50W` のように**英数字になる**。
`「…」` が無いと、経歴を書いても**和文の型で使えない**。

当初の設計では「和文で使うなら読み (`エフティー キュウキュウイチ`) を入れる」としていたが、
**運用者の実際のやり方は読みではなく欧文のまま送ることだった。** 読みの欄の意味が変わるので、
こちらを先に決める。

---

## 3. 規則

**差し込んだ後の文に `「…」` があれば、その中は欧文で符号化する。**

どこに書かれていたかは問わない。**経歴の値に書いても、型に書いても同じように効く。**

```
経歴: リグ = 「FT991」
型:   {HORE}リグ ハ {リグ} デス{RATA}      <- 型は「リグが欧文だ」と知らなくてよい
差し込み後: {HORE}リグ ハ 「FT991」 デス{RATA}
```

### 3.1 和文の中では

| 記号 | どうする | 理由 |
|---|---|---|
| `「` | **出さない** | どちらの符号表にも無い。出しようがない |
| 中身 | **欧文の符号表**で送る | |
| `」` | **和文の符号 `・-・-・・` として出す** | 区切りとして相手に届く |
| ホレ・ラタ | **付けない** | 運用者の実際のやり方 |

```
電波: リグ ハ  ->  F T 9 9 1 (欧文)  ->  」  ->  デス
```

`「` が出ないのは非対称だが、**符号表に無いので出しようがない**。
閉じる `」` だけが区切りとして届く。

### 3.2 欧文の中では

**括弧を両方落とす。中身はそのまま。**

```
欧文の型: RIG {リグ} ANT {アンテナ} K
差し込み後: RIG 「FT991」 ANT 「DP」 K
電波:      RIG FT991 ANT DP K
```

**`」` は和文表にしかない。** 欧文の文に残すと送れなくなる。
そして欧文の中では `「…」` は「ここは欧文」という意味を持たない (既に欧文である)。
**印が不要なので落とす。**

これにより**同じ経歴の値が和文でも欧文でも使える**。

### 3.3 対になっていないとき

**`」` は既に「和文の終わり」として使われている** (`reading.py` の docstring)。
`「…」` を欧文の印にすると衝突する。

**対になっているときだけ印として扱う。**

| 書いたもの | どうなる |
|---|---|
| `「FT991」` | 欧文区間 |
| `コンニチハ」` | 従来どおり和文の終わり |
| `「FT991` (閉じていない) | **印として扱わない。** `「` を落とし、中身は周りのモードのまま |

**閉じていないものを欧文区間として扱わない**のは、書き間違いで意図しない符号が出るのを
防ぐため。`「FT991` は和文モードのままなので `FT` が「送信できない文字」として見える。
**黙って通さない。**

### 3.4 入れ子

**入れ子は考えない。** `「` から次の `」` までを 1 区間とする。
`「A「B」C」` は `「A「B」` が区間で、`C」` が続く形になる。
実運用でリグ名を入れ子にすることはない。

## 4. どこに実装するか

`src/tx/encoder.py` の `split_segments`。いまはモードを切り替えるのが
`{HORE}` / `{RATA}` だけなので、そこに `「…」` を加える。

**`src/tx/reading.py` の `PUNCTUATION_MAP` は `「` を空文字に落としている。**
このままだと `split_segments` に届く前に `「` が消える。
**カナ変換より後に差し込むのではなく、括弧を残したまま `split_segments` へ渡す**必要がある。

実際の経路は次のとおり:

```
型 -> 欄の差し込み -> 日本語ボックス -> to_sendable_kana -> kana_view -> find_unsendable / encode
                                        ~~~~~~~~~~~~~~~~ ここで 「 が消えている
```

**`PUNCTUATION_MAP` から `「` を外す** (落とさずに残す)。`」` は元から残っている。
その代わり `find_unsendable` と `encode` が `「…」` を区間として解釈する。

**`「` が区間の外に単独で残った場合は、どちらの符号表にも無いので
「送信できない文字」として見える。** これは正しい振る舞いである (書き間違いが見える)。

## 5. 影響を受けるもの

| 場所 | どうなる |
|---|---|
| `encoder.split_segments` | `「…」` を欧文区間として刻む |
| `encoder.find_unsendable` | 区間ごとの表で判定する (既存の仕組みがそのまま効く) |
| `reading.PUNCTUATION_MAP` | `「` を落とすのをやめる |
| `reading.find_bad_chars` | `「` `」` を通す (マーカーと同じ扱い) |
| 例文 `設備の紹介` | `RIG {リグ}` をホレの中へ戻せる |
| 経歴の値 | `「FT991」` のように書く |

**`morse_tokens.py` は変更しない。** 符号表そのものは何も変わらない。

## 6. 異常時のふるまい

| 書いたもの | どうなる |
|---|---|
| `「FT991」` | 欧文区間。`」` を和文の符号で出す |
| `「FT991` (閉じていない) | 印にしない。`「` が送信できない文字として見える |
| `「」` (空) | 何も出さない。`」` だけ出る |
| `「コンニチハ」` (中身が和文) | **欧文区間なのでカタカナが送れず、赤く出る** |
| 欧文の中の `「FT991」` | 括弧を両方落とす |

**どれも黙って通さない。** 送れないものは「送信できない文字」として見える。

## 7. テスト

| 対象 | 見ること |
|---|---|
| 和文の中の `「FT991」` | 欧文区間になり、`」` が和文の符号として出ること |
| 欧文の中の `「FT991」` | **括弧が両方落ちること**。`」` が残らないこと |
| 単独の `」` | 従来どおり和文の終わりとして送れること |
| 閉じていない `「` | 印にせず、送信できない文字として見えること |
| 中身が和文の `「コンニチハ」` | 送れないと分かること |
| 経歴の値に書いた場合 | 型に書いた場合と同じ結果になること |
| 既存の `{HORE}` `{RATA}` | 振る舞いが変わっていないこと |
| カナ変換 | `「` が消えないこと |
| 例文 10 個 | **引き続き全部送れること** |

## 8. 確認できていないこと

- **`」` を区切りとして送ることが相手に正しく伝わるかは、実際の交信でしか分からない。**
  運用者は実運用でそうしていると述べている
- **入れ子を考えないことが実用上困らないかは未検証。** 困ったら規則を足す
- 長音 `ー` は使わない方針 (`FT-991` ではなく `FT991` と書く) だが、
  これは値の書き方であってコードの話ではない
