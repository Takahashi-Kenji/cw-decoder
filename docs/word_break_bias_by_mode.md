# 語間スペースの抑制をモード別にする 結果

実施日: 2026-08-25
対象: `src/infer/ctc.py` / `src/infer/settings.py` / `src/app/workers.py` / `web/src/ui/app.ts`
結論: **採用。** 欧文 −1.0 / 和文 −5.0。再学習なしで 欧文 −1.22pt / 和文 −4.07pt。

---

## 1. なぜ気づいたか

欧文 13.06% に対し和文 27.15% という 2 倍の差の理由を、実測で 1 つずつ潰していった
(すべて否定):

| 仮説 | 測り方 | 結果 |
|---|---|---|
| 打鍵の揺らぎ | σ 実測 0.030 dot | ❌ 機械打鍵。欧文と同一 |
| 速度 | L4 1200 件を 15〜30 wpm で分解 | ❌ 13〜16% と平坦 |
| 本文が難しい | 同じ本文を合成してデコード | ❌ 和文 2.30% (欧文 3.64% より**良い**) |
| 間隔が分布外 | 実測値 1.32/3.57/7.41 で合成 | ❌ 和文 2.23% (教科書 1/3/7 と同じ) |
| 振幅のずれ | ピークを 0.48 に正規化 | ❌ 変化なし |
| 信号が汚い | 深さ 26.8 dB (L4 は 9.7 dB) | ❌ **最も綺麗** |

残ったのは**誤りの中身**だった。

| | 正解の語間 | モデルの出力 |
|---|---|---|
| 欧文 | 50 個 / 245 トークン | **50 個** (ぴったり) |
| 和文 | 29 個 / 221 トークン | **52 個 (1.8 倍)** |

和文の挿入誤り 34 個のうち **27 個が語間スペース**。欧文と和文の TER 差は
ほぼこれで説明できる。**同じ録音・同じ打鍵なのにモードで真逆**だったのが要点で、
共通の値で調整していた過去の掃引ではこれが見えなかった。

過剰挿入の直前の文字は [ホレ] 5 回・`、` 4 回・残り 18 回は散らばり。
符号長で見ると **6 要素の直後に 3 倍集中** (本文中の出現率 11.5% に対し 33.3%)。
6 要素は和文にしかない長さである。

## 2. 掃引 (held-out 20 件、`scripts/sweep_word_break_by_mode.py`)

| bias | 欧文 TER / CER | 和文 TER / CER | synth_val | 和文の語間 (正解 29) |
|---|---|---|---|---|
| 0 | 13.06% / 12.20% | 27.15% / 34.14% | 45.00% | 52 |
| **−1** | **11.84% / 11.02%** | 26.70% / 34.14% | 45.49% | 50 |
| −3 | 12.65% / 11.81% | 25.34% / 32.93% | 46.03% | 45 |
| **−5** | 13.88% / 13.78% | **23.08% / 31.33%** | 46.62% | 40 |
| −8 | 17.14% / 18.50% | 22.17% / 30.92% | 47.84% | 30 |
| −12 | 27.35% | 23.53% | 50.99% | 1 |

**最適値がモードで違う** — 欧文は −1 が底、和文は −8 が底。共通の値では
どちらかを犠牲にする。

**CER (スペース込み) も同じ向きに動く。** 語間を減らすと「語がくっついて読めない」
という元々の苦情 (docs/word_break_bias.md) が戻る恐れがあったが、和文は −5 まで
TER も CER も改善した。

## 3. 採用値

| モード | bias | 効果 |
|---|---|---|
| 欧文 | **−1.0** | TER 13.06 → 11.84% / CER 12.20 → 11.02% |
| 和文 | **−5.0** | TER 27.15 → 23.08% / CER 34.14 → 31.33% |
| 自動 | **和文と同じ** | ホレ/ラタ が実信号でほとんど認識できず自動切替が働かないため (運用者の判断) |

synth_val は 45.00 → 46.62% (+1.62pt)。採用条件の「+3pt 未満」に収まる。

**2026-07-31 の掃引との違いを明示しておく。** あのときは β=−3.0 と確信度閾値
τ=0.95 の**併用**で synth +2.75pt となり不採用にした。今回はロジットバイアスのみ、
かつモード別。また当時の keyed 値は**汚染されたラベル**で測っていた (23.35%)。
なお「+3pt 未満」という条件は 2026-08-24 の計画で設定したもので、当時の判断者は
より厳しい基準を採っていた。

## 4. 限界 (根本解決ではない)

- bias −8 まで押しても和文の語間は 52 → 30 までしか減らない。**モデルは強く確信して
  出している。** 過剰挿入の背後には、まだ名前の付いていない原因がある
- 語間を正解の数に合わせても和文は 22% 止まり。置換 14・脱落 12 は残る。
  **語間だけでは欧文の 13% には届かない**
- ブラウザ版はモード別に持てない (1 回のデコードを欧文と和文の両方に描くため)。
  両方が改善する −1.0 を既定にした。`?wb=-5` で和文寄りにできる

## 5. 再現

```bash
python scripts/sweep_word_break_by_mode.py \
  --ckpt models/full/best_infer.pt --keyed-dir data/keying_scripts \
  --noise-dir data/noise/val --bias 0 -1 -3 -5 -8 --out models/eval/wb_by_mode.json
```
